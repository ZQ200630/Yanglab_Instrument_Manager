# Native TLB-6700 integration

The catalog binding is tlb6700 / laser / newport-usb. Production is GUI → Rust Host
→ native protocol-3 Worker → linked yang-lab-tlb Bus → Newport SDK. One lazy
bounded owner executor constructs, calls and drops the non-Send SDK/Bus/guard on
its owning thread. There is no Python scheduler, ctypes path or TLB executable
bridge in the App. The standalone TLB CLI and historical Python adapters remain
excluded diagnostic/reference source.

## Prerequisites and identity

Newport USB Driver 5.0.8 provides the fixed x64 SDK path and WinUSB device binding.
NI-VISA/NI MAX is not required for this controller; other instruments retain
their vendor dependencies. Settings and profile prerequisite checks read present
USB metadata and the SDK PE header without loading SDK, discovering controllers
or opening a port. A compatible SDK file is not communication proof.

Metadata preserves Newport {devices,sdk,download_url,install_note} and independent
USB serial {ch340,cp210x} shapes. Only problem 28 is missing; ready requires
problem 0 and approved service; absent/unknown/fault remains non-installable.
Newport's missing-SDK install case remains available even without controller rows.
CH340/CP210x empty families are not_detected, never missing.

Explicit scan_lasers is a separate admitted SDK action. It returns unique bounded
controller records only after successful preserving cleanup. Connected, queued,
busy or retained owner state refuses competing scans; failed cleanup returns no
partial success and keeps release false. Installer admission reads cached
newport_resources_released; it never queries SDK to infer release.

Controller keys are exactly 6700 SN<serial>. Fresh controller/head identity is
verified at connect/probe; head swaps invalidate authority. COM order, USB address
and cached SDK description never establish identity. Separate controllers share
one owner; closing one does not globally close another. Normal close/disconnect
preserves output, remote and tracking settings. Uncertain/blocked calls keep
responsibility and exact attempt evidence without replay.

## Controls and limits

Code/Utils/tlb_models.json is the shared published hardware table used by the
linked Bus and Host. TLB-6722-P uses the 6722 envelope: 1045–1085 nm, 10 nm/s.
-P denotes permanent fiber coupling. Unknown/custom heads cannot tune/start/enable;
the original confirmed composite stopping allowances remain Output(false),
Tracking(false) and ScanStop, with unchanged fault/preflight rules.

Saved operating_min_nm, operating_max_nm and scan_speed_limit_nm_s are collective
narrowed limits. Changing them requires a released quiescent domain and current
revision. The Host persists the revision, activates it in Worker before a later
connection and fences admission if activation is unconfirmed. Fresh head identity
and the native driver independently constrain every setter; frontend validation
is not the safety boundary.

Typed wavelength, piezo, output, tracking, remote and scan actions require the
reviewed confirmation and argument schema. Power/current controls are unavailable
because this table establishes no operating envelope for those quantities.
Action acknowledgement sets motion pending; physical completion comes only from
later bounded motion evidence. Full telemetry and motion reads retain separate
acquisition ages. New motion/status never refreshes older power/current/output
samples. Readback failure does not repeat an acknowledged setter.

The console labels the complete single cycle Full Scan and the hold-position
interrupt Stop Scan. Scan shortcuts can be configured, enabled or disabled and
are saved locally; Escape Stop is the only default binding. Shortcuts follow the
current enabled button and its usual authority checks.

Forward/Backward single-pass actions use the typed shared movement lifecycle.
Their capability and individually reviewed rates are forwarded from the loaded
SDK through the native driver and Worker to the console. Admission rejects an
unreviewed rate before any setter, including an inherited-Tracking stop. A fresh
naturally complete endpoint with Tracking already off completes without another
setter. Stop and emission retain their independent authority rules.

RESET's actual slew is not established by the manual's endpoint description or
a stored rate readback. Production support therefore requires a reviewed record
compiled into Code/Utils/tlb_native/src/reviewed_single_scans.json. Records bind
the exact controller, firmware, laser head and head serial to the actually loaded
SDK SHA256 and protocol revision. There is no runtime, environment or operator
qualification override. Empty, malformed or mismatched records remain unsupported;
changing a head or SDK invalidates its qualification.

The development-only yang-laser-scan diagnostic requires separately authorized
enumeration, read-only connection and bounded reversible probes. Its offline
--review command recomputes rate, direction and one-second stopped-hold evidence
from six immutable real reports: both directions at 0.05 and 0.1 nm/s, plus midway
Stop in both directions at 0.1 nm/s. It also requires unchanged emission and
blanking readbacks, exact common identity/SDK and preserving resource release.
The resulting profile is review input, never installed automatically. Qualification
uses controller readback with coarse tolerance; it is not an optical wavelength,
speed or blanking measurement. Current compiled records remain empty pending
physical acceptance. See the dated single-scan validation record.

## Fixed driver installation and offline verification

The App carries the three approved vendor packages, their original 18 file pins,
licenses and provenance READMEs. CP redistribution attestation remains explicit.
Newport MSI hash pinning does not establish a publisher signature. A fresh
positive missing check, all leases AVAILABLE, disconnected status and cached
Newport release true precede an explicit Install action/UAC. Windows System32
msiexec/pnputil only receives the fixed package; no caller path, downgrade or
automatic reboot. Installer completion, cancellation, failure, no-change,
reboot-required and unconfirmed exit do not imply driver readiness. Startup and
App installation do not install drivers.

~~~powershell
./App/scripts/test-native.ps1 -Offline
~~~

The root locked workspace runs finite owner-thread/transport, head/limit, ACK/age,
scan retention, metadata, Host, frontend and package checks without SDK loading.
[Native development](development.md) gives PortableOnly and prepared NSIS commands.
Both contain a linked Worker and identical exact resource allowlists.

This merged source has no new real SDK, hardware, installer or clean-Windows
acceptance evidence. Prior dated physical observations remain historical in
[legacy TLB notes](development/legacy-tlb6700.md) and dated validation records;
they do not qualify the new merged artifact. Real diagnostics still require
separate enumeration, read-only connection and reversible-action authorizations.
