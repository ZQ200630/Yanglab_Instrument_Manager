# Real-only Instruments Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. The operator automatically approved equivalent design/plan handoffs on 2026-10-06; execute inline without waiting for another reply.

**Goal:** Remove every executable instrument simulator and make ordinary App/experiment operation use only real, identity-verified drivers.

**Architecture:** Change the existing worker/native/GUI startup contract together so no producer can still launch a removed backend. Preserve real identity/proof/resource/lifecycle boundaries, quarantine legacy non-real authority, then remove experiment and dormant simulation execution paths. Pages/archives and TLS multi-Host functionality follow as separate plans implementing the same approved spec.

**Tech Stack:** Python in Anaconda VISA, existing Rust/Tokio/Tauri Windows runtime, native JavaScript modules and Node's test runner; no new dependency for this increment.

**Spec:** `docs/superpowers/specs/2026-10-06-real-console-design.md`

## Global Constraints

- Reusable drivers stay in Code/Utils; diagnostics in Code/Debugs; reference_code is read-only; results in Result/<name>.
- All Python commands use `D:/SoftwareInstaller/Anaconda/envs/VISA/python.exe -B`.
- No fallback/synthetic readings or fabricated resource/identity evidence. No automatic instrument opening/output restoration at Host startup.
- Preserve Voltage 0-14 V, <=0.1 V steps/>=50 ms, fault zero; Gain 0-200 mA, 15-40 degC, five-second +/-0.2 degC interlock, current-off before TEC-off.
- MDT faults hold, never auto-zero; motion remains through Fiber setup with serial-bound sides and existing limits.
- Keep boot/domain/revision/epoch/proof expiry, release evidence and no-replay gates.
- Do not merge into main, delete user results, rewrite historical provenance or change global Git/Tailscale configuration.
- Tonight's automatic hardware consent is used for identity/data reads and disclosed safe shutdown/zero only; no unattended nonzero voltage, current enable, TEC enable or stage motion.

## Review Focus

- An old running Host must not become real merely because preferences say real; test attachment rejection before actions.
- Mixed real/legacy device records must preserve real records while revoking every non-real identity/check consent.
- Constructor/factory changes must not open resources during startup or unit tests; fail on accidental external open.
- A worker rejected obsolete arguments must exit before discovery or driver construction, not quietly choose a backend.
- Historical synthetic experiment manifests must not be resumed as hardware runs after CLI cleanup.

## File structure

- Worker entry/controller/verification/resources own real factories and wire provenance; no synthetic module.
- Native runtime/Host CLI/GUI/preferences/registry own launch compatibility and durable migration.
- Existing web Host client/settings own presentation and attachment compatibility; no mode selector.
- Experiment run/storage modules own real execution and historical-run rejection.
- New `App/tests/test_real_only.py` and `App/tests/real-only.test.mjs` exercise behavioral rejection/factory/GUI boundaries; existing Rust module tests cover migration/startup.
- Code/Debugs and Result/console own actual staged acceptance, not unit-test fabricated instrument sessions.
