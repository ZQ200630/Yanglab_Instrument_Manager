# PM400 and MDT693B Drivers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build complete, typed, robust drivers for the Thorlabs PM400 optical power/energy meter and the three-channel Thorlabs MDT693B piezo controller, plus offline tests and deliberately staged hardware diagnostics.

**Architecture:** Implement two independent drivers because PM400 uses atomic VISA/SCPI transactions while MDT693B uses prompt-terminated serial transactions plus a background read-only monitor. Both reuse the existing lifecycle and exception taxonomy, expose immutable typed snapshots, preserve the instrument state on connect and ordinary close, and keep all transport details out of experiment code. PM400 and MDT693B are separately testable deliverables; only the final export/documentation task joins them.

**Tech Stack:** Python 3.10 in Anaconda environment `VISA`; PyVISA; PySerial 3.5; standard-library `dataclasses`, `datetime`, `enum`, `threading`, `time`, `unittest`, and `unittest.mock`.

**Spec:** `docs/superpowers/specs/2026-08-19-pm400-mdt693b-drivers-design.md`

## Global Constraints

- Treat `C:/Users/PIC_YangLab/Downloads/mtn007145-d02.pdf` and `C:/Users/PIC_YangLab/Downloads/ttn011225-d02.pdf` only as protocol references; the approved spec and `AGENTS.md` control safety behavior.
- Run every Python command with `conda run -n VISA`.
- Put reusable drivers only in `Code/Utils` and diagnostics/tests only in `Code/Debugs`.
- Experiment code must never open these VISA or serial resources directly and must never bypass driver limits.
- PM400 connect and close may query identity/capability and release resources, but may not reset, clear status/errors, zero, change range, or change measurement configuration.
- PM400 must expose every remotely documented command and reject sensor-incompatible operations before any write.
- PM400 reset, zero collection, detector-response changes, adapter-type changes, and status preset require `confirm=True` as specified below.
- The PM400 driver closes a `ResourceManager` only when it created that manager; it always closes its own instrument session.
- A process-local VISA registry must reject a duplicate open of the same canonical resource, while different canonical resources may operate concurrently with independent locks.
- MDT693B is three-channel, 115200 baud, 8-N-1, no flow control, with bounded read/write timeouts.
- MDT693B connect and ordinary close are read-only with respect to settings and outputs; they must preserve echo, Master Scan, axis voltages, and all configuration.
- MDT693B software ceiling is exactly 75.0 V even when `vlimit?` reports 100 V or 150 V; lower application ceilings are allowed.
- Every ordinary MDT693B output change uses steps no larger than 0.1 V and intervals no shorter than 0.050 s.
- MDT693B faults stop and hold. No communication, confirmation, monitor, cancellation, or close fault may silently zero or otherwise move the stage.
- Only `ramp_to_zero()` and `emergency_zero(confirm=True)` are allowed to intentionally zero the piezo, and both must verify X/Y/Z readback.
- The default MDT693B monitor rate is 2 Hz and it performs only X/Y/Z queries.
- Public APIs do not expose arbitrary raw SCPI/serial writes.
- Catch `BaseException` at cleanup boundaries, preserve the primary exception, retain cleanup evidence, and never report `DISCONNECTED` while a resource or monitor may still be alive.
- The workspace is not a Git repository. Each task ends with a reproducible test checkpoint instead of a commit.
