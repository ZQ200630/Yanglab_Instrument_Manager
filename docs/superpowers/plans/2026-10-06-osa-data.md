# OSA Capture Archive and Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans inline, task-by-task, with one whole-plan independent review. The operator selected inline execution and automatically approved equivalent planning handoffs; retain that choice. Steps use checkbox syntax.

**Goal:** Read real existing OSA traces from the App, preserve them across Host restarts, and display/export verified native samples without oversized control replies.

**Architecture:** A bounded worker spool transports completed native captures in small chunks; it is delivery staging, never the durable archive. The owning Rust Host verifies the complete payload before sealing an immutable capture archive under its configured Result root. GUI observers consume archive references and verified chunks; neither plotting nor export reopens hardware.

**Tech Stack:** Existing Anaconda VISA Python/NumPy, Rust/serde/Tokio/SHA-256 and vanilla JavaScript; no new dependency.

**Spec:** docs/superpowers/specs/2026-10-06-real-console-design.md, section 3 OSA and the spectrum-capture portion of section 4. Approved OSA driver increment is committed through 31d8666 after one final independent review and one tested fix pass (see docs/superpowers/osa-trace-review.md).

## Global Constraints

- Every Python command uses D:/SoftwareInstaller/Anaconda/envs/VISA/python.exe -B. No selectable backend, invented device/sample, unknown-instrument probe or main merge.
- Preserve the existing 65536-byte control frame limit. Native reads permit <=200001 samples, dBm or absolute W only, with consistency unproven. The requested trace must already be active on the OSA panel; no implicit selection/format/sweep/abort.
- Public driver use only. Storage and spool live in App modules, never Code/Utils. All native values remain byte-exact float64 values supplied by TraceCapture, not plotted/downsampled values.
- Archive retrieval is historical read-only, not a source of live identity proof or command authority. Existing local SID/PID, lease, operation/configuration/boot fences and separate safety scheduling stay intact.
- Developer archive root defaults to the workspace Result tree; installed Host root is selected/persisted in Settings. GUI supplies a validated short archive name, never a filesystem path for a data chunk.
- No new physical sweep tonight. Real acceptance may read the already identified GPIB0::4::INSTR only after fresh offline gates and scope disclosure. Native GUI acceptance cannot be replaced by browser or fixture output.

## Review Focus

- A maximum 200001-point capture exceeds the Host control-channel envelope: every new capture/chunk control reply stays within 65536 bytes and no half-capture appears complete. The legacy worker reader's 17 MiB guard remains unchanged; it is not the reason to enlarge Host IPC frames.
- Disk-full/worker death/cancellation during staging: mark a partial archive, retain primary error, never silently resweep or restore hardware outputs.
- A restarted Host serves an old capture: provenance/hash survive, but no old lease/proof/boot identity is reactivated.
- Two local/remote observers request the same completed operation: the owning Host archives once, deduplicates by operation identity and shows the same sample hash.
- Traversal, reparse-point or mismatched chunk/metadata input: no outside file access and no content published before length/hash/native-schema validation.

## Files and interfaces

- Create App/worker/captures.py and App/tests/test_captures.py: immutable native capture descriptor, bounded file spool and binary payload encoding. No driver construction.
- Modify App/worker/controller.py, domains.py, contracts_v3.py, main.py, catalog/model operations and corresponding tests: typed read_trace action, small descriptor reply, historical staging read/ack methods and exact owner-provided spool directory. Retain legacy acquire but route completed data through the same bounded staging rather than a giant spectrum JSON.
- Modify App/src-tauri/src/runtime.rs only for owned worker spool configuration and strict descriptor/chunk validation; do not raise existing frame limits.
- Create App/src-tauri/src/host/archive.rs plus tests; modify host contracts/service/configuration and native App command/client bindings: persistent capture actor, selected root, import/retrieve/list/export, operation-result reference and restart recovery.
- Create App/web/osa.js and App/tests/osa.test.mjs; modify panels.js, operations.js, shared-results.js and relevant native/frontend client bindings: concise native-unit plot/cursor/list and verified archive fetch/export. Keep other device controls unchanged.

Transport payload is consecutive little-endian float64 pairs `[wavelength_nm, native_value]`, exactly `sample_count * 16` bytes. Metadata travels separately and carries native unit, trace/identity, actual read interval/elapsed time, before/after contexts and consistency. Never encode arrays into the terminal JSON. Descriptor schema is version1: kind=`osa_trace`, opaque32-hex capture_id, point_count1..200001, byte_count=point_count*16, SHA-25664-hex, metadata object <=8192 encoded bytes. Only wavelength-panel context (x_unit=0) is admitted until typed frequency context support is validated. The worker spool is bound to its Host-created ownership nonce; maximum32 entries and128MiB total physical bytes, including orphans. Duplicate id with different metadata/content fails. Read chunks are <=16384 raw bytes (<=32768 hex characters) so envelope plus metadata remain bounded. Chunk replies contain capture_id, offset, byte_count, sha256 and data_hex; offsets must be within the complete payload and the exact returned byte count is checked. Only an acknowledged complete transfer may remove its staged entry; failed removals remain capacity-accounted.

Archive root/name/recording_id paths are constructed by Host code. Names are1..40 ASCII letters/digits/hyphen/underscore, beginning with a letter/digit; IDs are32 lowercase hex. Validate canonical parent containment and reject symlink/reparse escapes. Each one-shot capture archive has immutable manifest.json, native.bin and a separately atomically written complete.json marker containing both hashes and exact lengths. An unsealed directory is partial/interrupted, never complete. Manifest preserves Host ID, domain/device identities, config revision, original operation ID, source kind=real, native metadata and archive creation time (not instrument measurement time). Completing/copying an archive never rewrites its manifest. Export produces native CSV plus original manifest; GUI save destinations go through the native save dialog/path authorization rather than arbitrary chunk paths.

## Self-review / later increments

The three tasks form one dependent capture pipeline, not a new generic experiment engine. Signatures/count/endianness/chunk size agree, and every Review Focus condition belongs to a named test step. Task1's explicit acquire_trace public API keeps acquire->Spectrum compatibility, with its own RED-to-GREEN tests—never read twice or derive metadata from a display DTO. Staging IDs are generated by the worker; the Host's original operation ID is separately preserved as the archive deduplication/provenance key.

Telemetry/motion recording, Record/Stop scheduling and fail-safe recording policy for Voltage/Gain/PM/Fiber remain a subsequent data-service increment; this plan does not claim the rest of section4 complete. TLS, network-only acceptance profile, multi-Host GUI/Tailscale and physical Gain-probe/absent-device issues also remain separate. The operator's broad automatic approval does not authorize unsafe unattended nonzero outputs, motion or global Tailscale changes.
