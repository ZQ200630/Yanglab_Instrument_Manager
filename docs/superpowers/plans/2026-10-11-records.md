# Records Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development task-by-task.

**Goal:** Deliver interactive calibrated waveforms, explicit manual Save record, a unified Record/Data library and provenance-aware analysis together with the preceding repairs.

**Architecture:** Native bounded volatile previews share the existing runner but not durable Experiment storage. Existing waveform and OSA storage are adapted to the Records UI without rewriting payloads. A reusable plot interaction controller provides zoom history and native viewport refresh.

**Tech Stack:** Rust, existing native Host/Worker, JavaScript/SVG, Tauri/NSIS.

**Spec:** docs/superpowers/specs/2026-10-11-records-design.md

## Global Constraints

- Manual Acquire does not write a saved Record; Experiments still commit durably before ACK.
- Native previews have a 512 MiB aggregate budget; UI viewport max is 8192 points/channel (normal request 2048).
- Preserve actual calibration/raw samples, old saved records, immutable OSA seals, remote authority boundaries and previous dirty-tree repairs.
- No hardware commands in offline validation; install only after App/Host stopped. No push/merge.

## Review Focus

- Save/export while a new capture finishes must bind the selected preview, not the latest page state.
- Different channel calibration or hiding CH1 must not move the physical time axis/ROI.
- Delayed zoom/save replies after navigation/new capture must not replace newer data/drafts.
- Restart must not present an unsaved preview as a recovered saved record.
- Paired historical access must not expose another client's transient preview or add automation permissions.
