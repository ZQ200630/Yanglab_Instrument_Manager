# Connections and Pairing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. The operator's previously selected inline execution method is preserved. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace manual fingerprint/code input with Request connection → displayed-number comparison → Approve, and present paired computers in two simple Connections tabs.

**Architecture:** Keep the existing pinned TLS device transport and DPAPI records. Add a dedicated, bounded pairing-only TLS bootstrap, persist trust only after local owner approval, and then use ordinary authenticated connections. Split request state/comparison, wire exchange and UI state into focused modules; leave instrument/lease/archive behavior unchanged.

**Tech Stack:** Existing Rust 1.88+, Tokio, rustls 0.23.45 / tokio-rustls 0.26.6 / ring 0.17.14, Tauri and vanilla JavaScript. No dependency changes.

**Spec:** `docs/superpowers/specs/2026-10-06-pairing-design.md`, approved 2026-10-06. This plan itself is awaiting operator review before implementation.

## Global Constraints

- Work in the existing isolated `codex/pic-desktop` worktree. Do not merge/publish to main or 1060; preserve unrelated work and immutable evidence.
- No hardware operation, instrument simulator, installer, cloud service, automatic PC discovery or Tailscale/firewall change.
- Keep English/white UI, additive local/remote devices and the existing one-physical-Host guard. Pairing must not open an instrument, acquire control or replay commands.
- TLS 1.3 only; bootstrap uses a full handshake with no resumption/0-RTT. Existing saved certificate pins remain mandatory for authenticated traffic; no fallback on pin mismatch.
- Keep 65,536-byte frames, TLS/first-frame deadlines of 10 seconds, at most sixteen trusted peers and the existing eighty-channel semaphore.
- New requests: 120-second total deadline; four live pending requests; one per requester ID; five accepted starts per observed source IP per 120 seconds; twenty globally per 120 seconds; rate bookkeeping capped at 32 source entries. Use monotonic time and reject new sources when full with unexpired entries.
- Private keys, credentials and exporter bytes stay native/DPAPI protected. Only public comparison/request state reaches JavaScript. No raw SCPI or driver changes.
- Every Python command runs in Anaconda VISA. Native/web tests run offline; real TLS tests use new isolated storage, not the operator's trust/configuration.
- Preserve the old manually pinned/code-gated wire method for diagnostics/old clients, with all original gates; new UI never exposes those inputs or silently downgrades.

## Review Focus

1. The owner approves as the requester cancels/closes: expose possible orphan authorization honestly, never report guaranteed trust removal (Tasks 1–3).
2. The same owning Host is entered through another address: check its saved identity/pin before saving anything; do not treat the alias as permission to replace trust (Task 2).
3. Owner polling or a page/tab change occurs mid-entry/request: preserve address/nickname and native request state without replay (Task 3).
4. One bootstrap transcript is forwarded through two terminated TLS connections: the independently derived comparison values must differ for chosen test vectors; never display a server-supplied number (Tasks 1–2).
5. The requester persists trust but ordinary connect fails: show Paired / Offline and allow a separate Connect, not a new pairing attempt or instrument command (Task 3).

- Create `App/src-tauri/src/remote_pairing.rs`: pure comparison/transcript validation, bounded request/rate state. Its in-file tests cover deterministic clocks and vectors.
- Modify `remote.rs` / `remote_tests.rs`: integrate that queue with current encrypted peer storage and local approval. Do not move existing release proof/normal authentication code.
- Create `App/src-tauri/src/pair_transport.rs` and `pair_transport_tests.rs`: actual pairing-only client/server TLS exchange, version/phase validation and independently calculated comparisons. Register modules in `lib.rs`.
- Modify only remote-listener/pairing/local-management branches in `host/service.rs` and allowlists in `gui.rs`: pass observed TCP source, listener generation and cancellation into the transport. Add local-only Reject.
- Modify `remote_gui.rs` / `main.rs`: native-owned request tasks, three Tauri commands and close cancellation; keep existing five authenticated device channels.
- Create `App/web/connections.js`: accessible rendering, address normalization and public request state. Integrate through `setup.js`, `console-ui.js`, `host-client.js` and `style.css`; retain other Settings sections.

Existing legacy methods stay callable.

### Task 2: Actual pairing-only TLS transport and owning-Host admission

**Files:** `pair_transport.rs`, `pair_transport_tests.rs`, `lib.rs`, pairing/local-management portions of `host/service.rs` and `gui.rs`, `remote_tests.rs`.

**Interfaces:** Consume Task 1's store methods. Define `PairIdentity { id:String, name:String }`, `PendingPair` (private TLS/transcript/certificate plus `public()` request metadata), and `open_pair(endpoint:&str, identity:PairIdentity, nickname:Option<String>, known:&[RemotePeer]) -> Result<PendingPair,HostError>`. `PendingPair::finish(self, cancel:watch::Receiver<bool>) -> Result<RemotePeer,HostError>` validates the terminal result and returns native-only trust for Task 3 to persist. Define `PairOwner<'a> { trust:&'a Mutex<RemoteStore>, generation:&'a AtomicU64, stopped:&'a AtomicBool, name:String }`; `serve_pair_v2(stream:ServerTlsStream, first:HostRequest, owner:PairOwner<'_>, source:IpAddr, admitted_generation:u64) -> Result<(),HostError>`. Owner local `remote_approve {id}` dispatches to the ticket's legacy/v2 path; `remote_reject {id}` rejects v2. Both stay forbidden over authenticated remote transport.

- [ ] **Write RED actual-TLS tests** for `same_channel_comparison_and_approval`, `terminated_relay_has_different_comparison`, `pending_pair_has_no_dispatcher_access`, `bootstrap_cancel_expiry_and_listener_change`, `bootstrap_protocol_phase_mismatch`, `saved_pin_and_alias_cannot_downgrade`, `four_bootstraps_leave_authenticated_capacity`, and `old_host_reports_update_required`. Assertions: two independent endpoint calculations match only on the chosen same-channel vector; forwarding the server's advertised comparison cannot override the client's calculation; a pending/malformed request cannot catalog/acquire/read archives; stale/replayed nonce/ticket/ID is refused; unapproved/failed requests persist no requester credential; a resumed/early-data bootstrap cannot create trust; legacy authenticated reconnect still works.
- [ ] **Observe failure:** `cargo test --offline --locked --manifest-path App/src-tauri/Cargo.toml --lib pair_transport`; require the new tests to fail for absent/incorrect behavior, not storage fixtures or native compiler setup.
- [ ] **Implement native wire exchange.** `remote_pair_v2` first frame has exact `{version:2,peer_id,name,nonce}` fields and a random v1 frame ID used as transcript request ID. Owner acknowledgment echoes binding fields plus ticket, owner ID/name and `expires_in_ms`; terminal frame echoes binding and phase Completed with credential or explicit error. Both validate envelope v1/ID and expected phase. Use RFC 9266 exporter label `EXPORTER-Channel-Binding`, empty context and 32 bytes on both completed TLS endpoints. Only this bootstrap connector may provisionally accept an unknown certificate while verifying handshake signatures; obtain/pin the actual presented DER hash, never a supplied hash. Disable bootstrap resumption/0-RTT and validate saved pins/owner aliases before saving. The requester deadline starts before connecting; its finish deadline is the earlier of that 120-second total and the received owner remaining deadline. Add a four-permit bootstrap semaphore inside the existing total channel admission; release permits and remove pending records on every exit. Do not hold synchronous locks across awaits or acquire the trust/clients locks in reverse order.
