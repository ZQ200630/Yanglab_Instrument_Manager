# Console 安全调度与状态可信度设计

日期：2026-10-03。状态：用户已在本对话以“确认。”批准本书面规范；详细实现计划见 `docs/superpowers/plans/2026-10-03-console-safety-dispatch.md`，计划尚待审阅和执行方式确认。本文不是实现完成声明，也不是实机操作授权。

## 1. 目的与范围

让控制台在 OSA 采集、Gain 温度稳定等待等长操作期间，仍能接收并调度其它设备的操作，尤其是 Voltage 全通道归零与 Gain 关电流。同时，界面必须如实区分已请求、驱动调用完成、状态读回、资源释放和未知结果。

用户已确认的方向是：一个持续运行的 Anaconda `VISA` Python 工作进程、按设备独立调度、安全关断优先、旧输出指令作废、Gain 状态按字段判断新鲜度。保留现有驱动安全边界，不引入第二个硬件工作进程。

本次只重构 `App/` 的传输、调度、状态和对应界面。`Code/Utils`、`Code/Setups`、实验代码和参考例程不在修改范围内。如果实现验证发现必须修改驱动公共接口，应停止该部分并另行提出设计，不访问驱动私有成员来绕开限制。

仪器外观的目标仍是“让人认出仪器”，不是三维操控。本规范不增加或重做 3D 场景；静态识别卡片属于独立界面议题，不随此次架构确认一并实施。

## 2. 当前问题与依据

以隔离工作树提交 `92f6190` 为核查基线：

- `App/web/main.js` 的全局 busy 状态会阻止其它设备操作和状态轮询。
- `App/src-tauri/src/worker.rs` 在等待一个回复期间持有工作进程所有者互斥锁；停止请求也需要该锁。现有收包逻辑会丢弃与当前请求 ID 不同的回复，不能直接改成并发调用。
- `App/worker/main.py` 同步处理每一行，`controller.py` 又在整个设备调用期间持有全局锁。
- Gain 的 `read_status()` 返回缓存；温度 watchdog 只查询温度，却更新公共 `received_at`。用这一时间表示整组字段新鲜，会把旧 TEC/电流开关值显示成最新状态。

已有离线事件控制探针证实：阻塞模拟 OSA 采集时，Voltage 归零要等采集放行才能进入；真实 Gain 类的温度 watchdog 路径可刷新公共时间而保留旧的其它字段。这些是离线软件证据，不是对实机输出的测量。

## 3. 不变的安全约束

`AGENTS.md` 优先于界面便利性，现有驱动继续作为最终裁决者：

- Voltage：0–14 V，正常步长不超过 0.1 V、间隔不少于 50 ms；紧急归零使用 `zero(emergency=True)`。
- Gain：0–200 mA、目标 15–40 °C；TEC 开启且温度连续五秒在目标 ±0.2 °C 内，才可由驱动允许开电流。完整关断先电流、后 TEC。
- OSA：保留面板测量设置。现有公共取消路径是 `close()`，意味着断开，不是“取消后保持连接”。
- PM400：能力检查、危险操作单独确认、正常连接/关闭保留面板设置。
- Fiber：仅使用 `FiberCouplingSetup`，左右绑定、实验室坐标和位移限制不变；异常停止并保持，不自动归零或回滚。连接/恢复不自动重新建立位置估计或运动权限。
- 单一进程内的 VISA 资源租约和保留继续有效；不同资源可以并行，但不承诺不同进程之间的排他性，也不承诺底层 VISA 总线绝不竞争。
- 不强杀硬件工作进程、不自动重启或重连、不自动重放写操作、不直接发送串口/SCPI 数据。

“优先关断”只保证控制台不人为排在无关长任务之后，不是硬实时急停。操作系统、串口请求和 VISA 后端仍可能阻塞；软件不能替代硬件断电/联锁措施。

## 4. 方案与边界

采用单工作进程内的设备级调度。相比每台设备一个进程，它保留现有 VISA 租约语义和清理责任；相比仅增加 Python 优先队列，它同时去除前端、Rust 和输入循环中的全局阻塞。

```text
前端：各设备操作状态 + 独立安全控制
  → Rust：短时所有者锁 / 单写入器 / 按 ID 分发回复
    → Python：持续读入 / 有界调度 / 单回复写入器
      ├─ OSA     普通任务 + 受支持的 close
      ├─ Voltage 普通任务 + 优先归零
      ├─ Gain    普通任务 + 优先关电流/TEC
      ├─ PM400   普通任务
      └─ Fiber   setup 级普通任务 + close（保持输出）
```

Fiber 两侧在本次实现中仍共享一个 setup 调度域。允许只连接一侧；不额外引入左右独立运动并发。

### 4.1 组件职责

| 组件 | 责任 | 禁止事项 |
| --- | --- | --- |
| 前端操作状态 | 按 role 显示忙碌、关断中、未知、保留资源 | 用一个全局 busy 禁用所有安全按钮 |
| Rust broker | 进程所有权、请求关联、截止时间、进程退出证据 | 持有所有者锁等待设备回复，丢弃其它合法请求的回复 |
| Python ingress | 校验、分派、立即发布停止意图 | 在输入循环执行驱动 I/O |
| role 调度器 | 生命周期、代次、普通/安全操作和缓存 | 持有注册表锁执行驱动 I/O |
| 现有 controller 适配器 | 参数校验、公共驱动调用、结果分类 | 裸串口、裸 VISA、绕过 interlock |
| 状态缓存 | 发布不可变快照、字段证据和修订号 | 把缓存读取时间当成硬件采样时间 |

建议将调度和字段证据分别放入 `App/worker/scheduler.py`、`App/worker/observations.py`，将 Rust 回复路由抽入独立模块。只按职责拆分，不顺便重构无关仪器功能。

## 5. 请求与回复契约

### 5.1 协议版本与身份

升级为协议 v2，前端、Rust、Python、模拟桥和离线管道夹具一同迁移。启动握手必须核对 v2、VISA 解释器、包路径、运行模式和未连接状态；不兼容时拒绝进入可控状态，不降级到 v1。设置文件版本不因传输升级而改变。

工作进程创建不重复的 `session_id`；每次设备连接尝试创建新的 `connection_id`；每个 role 有递增的 `epoch`，安全操作/断开/会话关闭在接收时推进它。角色请求携带上述上下文，普通任务在接收和调用前均检查。过期会话或连接 ID 永远不能操作新的设备实例。尚未连接的角色使用明确的空连接身份及当前角色代次。

安全操作也必须匹配会话与连接身份，但允许使用该连接较旧的 epoch 来申请关断；不能因为安全按钮读到了稍旧的状态就拒绝同一设备的关断。具体操作是否属于安全白名单由后端决定，客户端不能自行声明“高优先级”。

### 5.2 Rust 回复路由

单一 stdout 读取器校验并按请求 ID 投递给对应等待者。所有者锁只用于取得/替换进程句柄和发布生命周期；等待回复、写管道、退出检查均不持有它。进程句柄在所有待决请求和清理责任结束前保留。

单一有界 stdin 写入器防止 JSON 行交错；写入器优先取安全控制，普通队列不能耗尽安全控制名额。活动普通请求上限 32；每个 role 保留一个安全操作槽，另保留一个全局关闭槽。拒绝超额普通请求而不是无限扩容。安全重复点击归并到正在进行的同一次操作，不创建重复驱动线程。管道本身若卡住，应明确显示传输未知，不能声称安全动作已送达。

只归并相同意图，不能把“关 TEC”当作正在进行的“关电流”而吞掉。Gain 的意图强度为关电流 < 关 TEC < 断开；Voltage 为归零 < 断开。更强请求升级同一协调责任，并向原请求报告升级后的实际效果；等待旧活动调用的阶段不能占住安全执行槽而阻止升级为 close。其它意图不作语义合并。全局关闭升级所有角色为终止关闭。

请求 ID 在当前活动集合和最近 256 个终态记录中不得重复；不提供自动重试或通用“恰好执行一次”承诺。超时但尚无终态的请求不从跟踪表中丢弃，继续占用有界槽位；后续回复仍会成为该请求的证据，绝不交给另一个等待者。

超时不等于取消。某设备请求超时只封锁该 role 的普通操作，保留状态、安全操作和清理入口；不能因为一次 `status` 成功就解除未知状态。传输整体失败则所有角色状态未知。收到旧 epoch 的成功结果可以记入历史，但不能恢复按钮权限、覆盖新状态或重新提交输出。

### 5.3 结果分类

每个请求只返回一个终态回复；进行中的状态通过快速缓存 `status` 查询显示。区分：

- `rejected_before_call`：未进入驱动，说明校验、权限或队列原因。
- `superseded_before_call`：旧代次队列任务已作废，未执行。
- `completed`：指定公共驱动调用完成；不自动等于物理输出已测量。
- `completed_readback_failed`：调用完成，但后续编码/读回未完成；禁止引导盲重试。
- `failed_after_call_started`：驱动调用期间失败，结果未知。

安全请求状态额外区分“已接收”“正在等待旧调用退出”“最终安全调用完成/失败”。前端刚发出请求只能显示“请求中”；必须收到工作进程缓存证据后才显示“已接收”。

## 6. 设备级调度规则

### 6.1 普通任务和所有权

每个 role 最多一个活动普通任务和一个待执行普通任务；更多请求立即拒绝。状态刷新仅保留一个合并后的待刷新意图，不逐次堆积。前端通常禁用同 role 的第二次普通提交；后端边界仍独立强制。

连接前，在短时注册表锁下原子保留角色及资源身份，然后释放锁执行连接。连接失败但释放未确认时保留设备对象、资源保留和错误证据；不因超时移除对象。序列号归属及资源规范化检查沿用现有实现与驱动，不能因并发把两个连接都放行。

采用固定数量的 role 普通执行槽、安全执行槽和观察槽，不为每个请求创建线程。观察槽只能执行明确允许的状态读取；命令和 close 不能从观察路径发出。Gain 公共读取内建的安全联锁关断是例外，其效果须如实记录。

`status` 只复制已经发布的缓存和调度信息，绝不现场遍历可能阻塞的驱动属性。仪器观察慢时只使该角色证据过期，不拖住整个状态回复。采集/移动后的结果发布均校验 session、connection 和 epoch。

### 6.2 安全白名单

| 意图 | 现有公共 API | 对正在执行任务的含义 |
| --- | --- | --- |
| Voltage 全通道归零 | `zero(emergency=True)` | 驱动已有取消代次；仍可能等待当前串口写入 |
| Gain 关电流 | `disable_current()` | 可与稳定等待并行；不会自动结束稳定等待 |
| Gain 关 TEC | `disable_tec()` | 由驱动保证先关电流；不是单独无条件发 TEC-off |
| OSA 停止并断开 | `close()` | 使用已有取消/释放协议；没有保持连接的取消承诺 |
| Fiber 停止并断开 | `FiberCouplingSetup.close()` | 保持电压，失去会话位置/权限；不承诺瞬时停止当前底层调用 |
| 关闭整个会话 | 每 role 的现有清理 API | 各角色独立清理，不等某台先完成才开始其它台 |

PM400 没有本规范新增的抢占式取消 API；活动调用不强行中断，断开先封锁新任务，再等待该调用结束后正常 close。界面明确显示等待中。

### 6.3 旧命令作废与“最终关断”屏障

接收安全意图时，在调度锁内推进 role epoch、锁住普通写入口、作废尚未执行的普通任务，随后立即调度白名单安全调用。连同 Rust 中尚未发送的旧请求，所有旧普通意图都必须在调用前被上下文检查拒绝。

已经越过调用前检查的任务算作活动任务，即使线程正停在进入驱动的前一瞬间。不能假设 Voltage 的内部取消 token 已经捕获，也不能假设 Gain 的关电流会取消稳定等待。

因此，保留连接的安全操作分两阶段：

1. 优先尝试安全调用，尽快利用驱动的现有取消/关断能力。
2. 等待此前活动的普通调用退出；若它与安全调用重叠，再执行一次相同的最终安全调用。只有旧调用已退出且最终安全调用成功，才报告该安全请求完成。

没有旧活动调用时只执行一次。所有尝试分开保留证据，不把第一次成功当成最终确认。等待期间保持普通写入封锁；旧命令晚返回不更新“最后有效设置”。若旧调用始终未退出或最终安全调用失败，显示关断未确认并保持封锁。该规则避免“先显示关断完成，旧线程随后重新加电”的错误承诺，但不声称活动调用在关断请求抵达瞬间就不可能再写。

成功的保留连接安全操作进入 `STOP_HELD`。用户显式选择“恢复普通控制”才可解除调度封锁；此动作只恢复接收新命令的资格，不写输出、不自动执行原输入框草稿。恢复需要旧任务已退出、最后安全动作有终态、驱动健康及当前连接身份已确认；不是驱动 fault recovery。未知或故障保持受限，只允许检查、再次安全尝试和关闭。Fiber 运动权限仍只能由 setup 的独立显式基线流程建立。

安全动作最终完成后，`STOP_HELD` 可以恢复允许的观察，以取得恢复普通控制所需证据；观察不会解除写入封锁。Gain 具有联锁效果的读取仍遵守第 8 节。读回成功不能自行清除停止锁存。

## 7. 关闭与异常处理

全局关闭在接收时原子进入 `CLOSING`，撤销各 role 普通任务和轮询意图。不同 role 的关闭责任同时分派；不再让 OSA 或某个失联端口阻止 Gain/Voltage 开始安全清理。

复用现有 `InstrumentSession`：每个 role 的清理责任由仅含该设备的 session 承担，再由 App 聚合每次不可变报告。Gain session 保留电流-off → TEC-off → close 顺序，Voltage 保留紧急零 → close，Fiber 仅 close。不改变通用 `InstrumentSession` 的实现或实验调用语义。已有安全操作与关闭合并到同一个 role 清理协调器，禁止两个 close 同时作用同一实例。

如果停止发生在连接过程中，立即封锁后续任务并记录待清理责任；连接调用的对象/保留不能遗失。调用返回后只进入清理，不发布可操作的 READY。未取得设备对象或调用未结束时明确显示连接/释放未知。

关闭成功必须同时确认驱动释放证据及有关活动调用已退出。调用卡住时保留对象、线程和资源保留；不以等待超时冒充结束。默认采用现有宿主预算（动作 180 s、连接/断开/关闭 90 s、普通请求 30 s、关闭回复后的进程退出核查 5 s）；这些是宿主报告截止时间，不延长驱动自身较短的期限，也不证明物理安全。缓存 `status` 使用单独 5 s 截止时间。

EOF 和可处理的主循环异常同样先发布关闭意图。清理未完成时不正常退出工作进程。输入管道仍可用时保留状态和显式重试入口；EOF 后不能谎称还可通过原管道重试，保留资源/进程与已产生的诊断证据，提示人工处理，不启动新进程争夺设备。不可恢复的进程崩溃只能报告结果未知，不能保证执行 finally。

每次清理尝试保留独立编号、步骤、未释放角色、Voltage 零证据及进程退出证据；后续重试生成新报告，不修改先前报告。保留已验证的原生失败关闭行为：未确认释放时不自动关闭窗口，不自动启动替代工作进程；原始失败报告仍可展开查看。进程确已退出但清理未确认时，显示 STOPPED 与清理未知两项事实，而不是显示“已安全关闭”。

宿主只缓存某次尝试的报告，不把失败报告当成永久终态：工作进程尚活且资源未释放时，用户明确重试可以发起新清理尝试；资源已释放但进程退出未确认时，只核查退出，不重做输出操作。

## 8. Gain 字段证据

### 8.1 数据模型

每个显示字段分别保存 `value`、`source`、`observed_age_s`、`quality`、`connection_id` 和观察修订号。`quality` 为 `fresh`、`stale`、`unknown` 或 `error`；历史值可保留，但必须附旧值/未知标签。观察时间只在 Python 的单调时钟中计算；前端保守加上本次状态请求的往返耗时和收到后的本地经过时间，不忽略传输延迟，也不拿两种时钟的原始值相减。

| 字段 | 可确立该字段读回证据的公共 API |
| --- | --- |
| 温度 | `read_temperature()` |
| 目标温度 | `read_target()` |
| TEC 状态 | `read_tec_enabled()` |
| 电流设定值 | `read_current()` |
| 电流开关 | `read_current_enabled()` |

每次成功调用只刷新其对应字段。保守使用本次调用开始时间作为观察年龄起点；慢请求不会被包装成刚刚采样。写入命令回复另存为“最后确认命令”，不替代独立读回，更不等于实际光功率或电流测量。

从写入开始就使受影响字段的旧读回证据失效，成功后再单独刷新；调用失败或结果未知不能恢复此前的 fresh 标记。关电流使电流开关证据失效；关 TEC 和故障联锁均使电流、TEC 两个开关的证据失效。特别是现有驱动注明开启电流会使控制板重置电流设定值，并在开启后重新读取；适配器不能沿用开启前的电流数值，也不能自行硬编码 3 mA 为实际读回。`disable_current()` / `disable_tec()` 成功返回 `False` 表示确认关闭，不是调用失败。

不要用整个 `GainStatus.received_at` 给任何一组字段统一盖新时间戳：连接时温度先读、其余字段后读、最后才赋该时间，初始温度也可能因此显得过新。本设计统一用适配器直接读取建立字段证据；缓存只作为明确标注的新鲜度未知的历史辅助信息，不从私有 watchdog 状态推断五秒稳定许可。

### 8.2 观察调度

连接后和普通操作完成后安排一次五字段刷新；平时每 2.5 s 安排一次，积压合并而不追赶。单次读取后检查停止意图再决定是否读下一字段，不把五个串口查询包成阻塞安全操作的大锁。

观察只在普通 role 空闲时执行；唯一允许并行的长普通任务是 Gain `wait_stable`，因为它等待 watchdog condition 而不长期占用串口请求锁。观察与普通写入的交接在单字段边界协调，避免一个旧读取在新写入后发布为最新；安全操作不等待该普通交接锁。观察线程和 watchdog 仍由驱动请求锁串行访问串口。若停止已接收，不开始新的常规观察；已开始的单个读取仍可能先完成，结果需经代次检查，不能承诺锁层硬优先级。

界面字段年龄超过 5 s 时标 stale；未成功读取过则 unknown。这个阈值仅用于界面保守控制，不修改驱动 watchdog 或稳定判据。一次刷新部分失败，只更新成功字段，失败字段保留原值和原年龄并标 error，不把整组状态清空后伪造 Off。

`read_tec_enabled()` / `read_current_enabled()` 是具有安全联锁效果的读取，可能发现非法组合并执行先电流-off、后 TEC-off 的故障处理；界面和文档不能称这组刷新为“绝不改变输出”。若读到 TEC-off 或有联锁异常，旧 current-on 证据立即失效，待独立电流状态读回，不用旧缓存强行恢复。读取抛错时，不能把内部曾收到但未成功返回的布尔值或故障缓存发布为成功读回。五字段刷新不是同一时刻的原子硬件快照。

### 8.3 操作显示

TEC/电流采用显式“开启”“关闭”，不根据缓存布尔值动态反转同一个按钮。未知不显示成 Off。关闭入口在忙碌或状态陈旧时仍可用，但驱动是否接受必须如实反馈。

电流开启需本连接关键字段已新鲜读回、TEC 确认为 On、调度权限有效。界面提示必须满足五秒稳定条件，但不以显示层年龄推导已稳定；实际 `enable_current()` 仍由驱动重读与 interlock 判定。稳定等待成功既不自动开电流，也不自动重放已作废命令。关电流与稳定等待并行时，显示“关断处理中；稳定等待尚未结束”，不显示“已取消等待”。

## 9. 前端交互

- 普通 busy 按 role 维护；OSA 忙不禁用 Voltage/Gain，也不停止总览缓存状态更新。
- 安全按钮有独立状态，不受普通 busy 限制。首次危险操作的现有确认保留；同一已确认安全操作的重复点击不再排入额外请求。
- 所有快照有 session/connection/epoch 和递增修订号；旧结果只能进入日志，不能覆盖新快照。页面重载只读取活动会话状态，不默认恢复写权限。
- 持续显示连接、请求状态、数据年龄与错误；不以旋转模型/动画表示真实硬件动作已经完成。
- 关断、断开或未知结果出现后清除该连接的待执行操作和授权上下文。文本草稿若保留，须标为未提交，不能自动提交；Fiber 原有权限和估计失效规则保持。
- 全局关闭和窗口关闭使用同一路径，显示各 role 的独立清理进度及不可变报告。

## 10. 验收契约

实现时先增加可确定复现的离线回归测试，再修改产品代码。使用事件/屏障控制顺序，不靠延长 sleep 来制造通过。所有 Python 使用 Anaconda `VISA`；本规范不授权实机枚举、连接或输出。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 阻塞 OSA acquire，同时 Voltage zero / Gain current-off | 两个安全调用均在 OSA 释放前进入公共 API；各自回复关联正确 |
| Voltage ramp + zero + 队列中旧非零请求 | 未开始的旧请求不调用驱动；完成归零后不再因旧请求输出 |
| 活动任务暂停在驱动入口前，随后安全请求先完成一次 | 不提前报告最终关断；旧活动任务退出后执行最终安全调用 |
| Gain wait_stable + current-off | off 可执行；等待未退出时不谎称已取消，最终状态不自动开电流 |
| 多个回复逆序、晚回复、重复 ID、损坏回复、管道 EOF | 不串包、不盲重试、不以旧回复恢复权限；明确关联/未知结果 |
| 普通队列满、安全重复点击、持续轮询 | 资源有界；安全名额保留；不创建无限线程/任务 |
| 某观察 API 被阻塞 | 全局缓存 status 及其它 role 仍可服务；相应字段自然变旧 |
| Gain 温度持续刷新而其它读回停止 | 其它字段变 stale/unknown，绝不随温度一起变 fresh |
| Gain 开启后电流设定重置、关闭返回 False | 旧电流证据失效并重新读回；False 正确显示为确认关闭 |
| Gain 读取出现 TEC-off/current-on、部分失败、初始缓存 | 不把未知当 Off；安全联锁可能的写入被真实说明，旧开关证据不复活 |
| 全局关闭时 OSA/PM400/某端口卡住 | Gain 与 Voltage 安全清理不等它们；Fiber 不归零；报告未释放角色 |
| connect 与 stop 竞争、释放未确认、重试 close | 对象/保留不丢失，不出现可操作 READY；尝试报告保持独立 |
| 同一 canonical VISA 并发连接/不同资源连接 | 重复资源失败；不同资源所有权互不混淆，不新建工作进程 |
| UI 重载、迟到快照、停止后恢复普通控制 | 不重放动作，不恢复旧 Fiber 权限，不自动更改任何输出 |

验证层次：Python 调度/适配器测试、Rust 实际管道并发测试、Node 生产前端交互测试、现有驱动离线回归、打包后的原生模拟验收。原生验收需补齐各仪器操作流程、忙碌时安全按钮、迟到结果和失败关闭；桌面不可访问时明确保留未验收项，不借用用户正在操作的窗口。

`SimGain` 同步补齐五个公共读取方法、缓存时间不因 `read_status()` 自行刷新、开启后电流读回变化以及与真实 API 相符的 TEC-off 顺序。模拟器用来暴露状态和并发问题，不能以较宽松语义掩盖真实驱动限制。

实机验收另外通过 `Code/Debugs` 按枚举、连接、可逆动作三阶段分别授权。通过全部离线测试也不意味着实机通信、紧急响应时间或物理零输出已经验证。
