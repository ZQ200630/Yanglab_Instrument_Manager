# 设备管理与本地远程 Host 设计

日期：2026-10-05。应用名称：Yang LAB INSTRUMENT CONSOLE。

状态：第二版设计已于 2026-10-05 获用户批准。用户已确认白色英文界面、精简说明、动态添加并保存本地设备、同一 Host 多台同型号设备，以及本地与远程设备的统一概览和点击入口。每台电脑拥有自己的 Host，操作由仪器所属 Host 执行，状态同步到所有获授权的 GUI。本版补充这些已确认方向所需的设备实例、探测、配置迁移和协议边界；批准本文件不等于批准真实硬件操作。

## 目标与范围

用户在电脑 A 的 GUI 中继续使用 A 的本地仪器，同时连接电脑 B 的 Host，使用 B 授权共享的仪器。A 对 B 仪器的操作通过 B 的本地驱动实际执行，B 的本地 GUI 与 A 的 GUI 都收到执行进度、读回状态和结果。B 在本地操作该仪器时，A 同样更新。

这不是远程桌面，也不是将驱动复制到访问者电脑。每台仪器只有所属 Host 执行硬件调用。界面中的远程仪器是对这台实体仪器的访问入口。

首版适配现有 AQ6370、Voltage Source、Gain Driver、PM400、MDT693B 驱动和 Fiber Coupling Setup，不能将尚无适配器的其它型号标成已支持。同一 Host 可登记和管理多台同型号设备，每台分别拥有设备 ID、配置、状态、请求、控制权和清理证据。类型是功能分类，不再是一个唯一设备槽位。不同 Host 可以拥有相同类型或相同资源地址文本的仪器，GUI 不能把它们合并。

首版不包含中心 Hub、云服务器、公共互联网访问、自动发现整个实验室、远程安装驱动、无人值守跨电脑实验编排或自动接管控制。软件所有标签、消息和按钮使用英文；设计文档可使用中文。

实施拆成两个有先后关系的子项目。第一阶段完成独立本机 Host 与 IPC、动态本地设备目录、注册与配置、按实例调度和控制、白色界面及新的 Overview；第二阶段扩展远程认证与控制、跨电脑事件同步及 Tailscale 接入。第一阶段不得以虚构远程设备或仅添加 REMOTE 标签冒充远程控制已完成。每个阶段分别编写实施计划和进行验收，后续不能因第一阶段界面已改好而宣称整个网络架构可用。

## 架构选择

采用独立 Host 进程，复用现有 Rust worker 管理与 Python 驱动边界。GUI 成为 Host 的客户端，本地与远程使用一致的设备操作契约。

曾考虑让 Tauri GUI 自身充当网络 Host。它能减少初期进程数量，但会将关闭窗口与终止他人使用的设备绑定，不适合当前需求。中心 Hub 与云中继则需要额外部署和管理，用户已选择不采用。独立 Host 的代价是增加一个需要显式管理的本地进程，但能分别表达窗口生命周期和仪器生命周期。

数据关系为：

```text
GUI A ──本地接口── Host A ── worker A ── A 的驱动与仪器
  │
  └──Tailscale 私有连接── Host B ── worker B ── B 的驱动与仪器
                           │
                         GUI B
```

Host B 将同一份获授权的设备状态发布给 GUI A 与 GUI B。B 不通过 A 的 Host 执行 A 发起的操作；GUI A 的远程客户端直接访问 Host B，避免中转链和循环转发。

### Host 的职责

Host 拥有一个 worker，管理本地配置、设备身份、资源预约、访问授权、设备控制权、命令责任、状态发布、操作记录及关闭报告。Host 不直接实现串口或 SCPI 协议，硬件调用仍经过 `Code/Utils` 和 `Code/Setups/fiber_coupling.py`。

每台电脑管理一个 Host。Host 启动前取得机器级实例所有权，并核对自身 worker 的存活记录；无法证明可独占时拒绝另起 worker，不以替换端口或杀进程解决。这个约束只保护本应用的合作实例，不保证其它软件或未合作 Windows 用户不会占用仪器。

### GUI 的职责

GUI 管理自己的设备视图、输入草稿和图表，以及到本机和其它 Host 的客户端会话。仪器卡片可来自多个 Host，但每张卡片必须显示所属电脑、设备身份、本地或远程来源、连接模式、状态新鲜度和当前控制者。

本地 GUI 也不能绕过 Host 单独打开驱动。GUI 的身份、已打开页面或按钮是否可点击，都不构成硬件操作权限。

### 对现有 App 的改动边界

现有 `App/web/api.js` 通过 Tauri 的 `worker_start`、`worker_request` 和 `worker_stop` 直接访问 GUI 所持有的 worker。独立 Host 需要从 `App/src-tauri/src/worker.rs` 提取可复用的运行时，保留 broker、请求名额、启动校验和失败清理责任，而不是复制第二套运行时。

网络层使用独立契约，不能把整个内部 worker RPC 暴露到网络。现有 v2 将请求和调度域绑定到固定 role，不能在不改变契约的情况下表达多个同类实例。本版采用显式的 worker v3：以 device_id 或 setup_id 选定一个登记的执行域，以 driver_kind 选择白名单适配器；Rust broker、Python worker、GUI 和模拟桥须协调升级，不能只在 UI 添加名称。

v3 保留严格字段验证、五种结果阶段、有界责任队列、安全优先入口、session_id、connection_id、epoch 和恢复屏障。上下文增加执行域身份，同一连接代次和 epoch 在另一个 device_id 上不能成立。v2 保持原契约用于旧版兼容和安全回归；一个 worker 启动时固定选择 v2 或 v3，不混用，不把 v3 身份丢弃后转成默认 role 请求。不认识的新版本拒绝，不静默降级。执行线程池保持固定上限，实例增加不允许无界创建调度线程。

角色变为适配器类型后，原先只有一份的 Gain 读回证据、巡检进度、最后命令、资源预约、Fiber 端口集合、清理报告、取消屏障和安全调度状态，必须改为按执行域保存。提取共同生命周期和证据逻辑，不能另造一套不受原有回归约束的远程执行路径。适配器仍只调用原驱动的公开方法，不放宽输出或联锁限制。

现有 App 源码在独立 checkout 中，主工作目录目前没有 `App`。后续实施须使用实际 App checkout，并保留尚未提交的英文 UI 修改；不能假设 App 已合入主目录。本设计文件保存在主工作目录的既有设计文档目录，不移动或合入 App 源码。

## 白色界面和导航

整个原生 App 使用白色卡片、浅灰页面与分区、深灰文字和蓝绿色操作强调。输入、选择框、通知、光谱图、趋势图及三维模型背景一起改为浅色，不能只修改页面底色留下深色控件。状态色需要浅色背景上的可读对比度；FAULT、输出危险和未知证据保留明确文字与图标，不仅依靠颜色。

删除 Overview 的 LOCAL SESSION 大标题、说明段和装饰横幅。将 Configure bench 收敛为工具栏的 Device Setup 入口。普通页面只保留必要字段和简短状态；完整身份、最近失败、清理证据和探测详情放到可展开区域。必须操作时出现的确认、故障和资源未释放提示不能因精简文字被隐藏。

主要入口为 Overview、Device Setup、Setups 和 Host Settings。仪器使用页由设备 ID 动态打开，不预置五个只能对应一个 role 的仪器入口。Host Settings 放本机 Python 路径、VISA 环境、模拟或真实模式、Host 启停及共享管理；这些运行时字段不占据 Device Setup 的主要空间。

### Overview 顶部

顶部显示 Local Devices 和 Remote Devices 两组状态概览，包括已登记实体设备总数、最近验证在线数及所属电脑的 Host 状态。远程部分按已成功配对、同步且获授权的 Host 汇总，不把仅保存的地址或尚未成功连接的电脑算成在线。

分母是可见的已登记实体设备数，不是仪器类型数，不再显示固定的五类。Fiber 复合 setup 在单独的 Setup 卡片中显示所含设备，不能既按 setup 又按两台控制器重复计入 Devices 总数。无设备时提供 Add New 和 Connect Remote Computer 入口，不生成 OSA 等默认虚假卡片。

### 仪器卡片和点击行为

下方 Instrument status 使用统一的设备实例卡片，显示自定义名称、型号、所属电脑、来源、通信状态、驱动状态、最近检查时间及必要的故障提示。本地和远程卡片使用相同布局。来源是 LOCAL 或 REMOTE；通信状态是 ONLINE、OFFLINE 或 UNKNOWN；READY、ACTIVE、BUSY、FAULT 和 RETAINED 属于不同的运行或责任字段，不能互相替代。

ONLINE 表示当前身份的通信检查仍在有效期内，不表示输出开启、驱动已就绪或客户端已有控制权。仅枚举到端口属于 Detected 证据，不能据此标 ONLINE。远程 Host 失联时，访问状态为 OFFLINE，真实仪器及输出状态为 Unknown，旧读数过期，不把它们改成零或 Off。

点击任一来源或通信标签、设备名称或 Open Instrument 入口，都打开 host_id 与 device_id 对应的仪器页，不执行连接、接管、恢复或输出动作。标签是导航，不是状态开关。离线或未知设备仍可进入查看配置和诊断，但普通硬件操作禁用。交互采用可聚焦的按钮或链接，键盘和鼠标行为一致。

已经展示的远程设备在暂时断线后保留，并显示离线与过期证据；重新联网先取快照。授权撤销后撤下对应设备并封锁旧页面，不能把上次配对时的许可永久视为有效。点击与后续请求都必须携带实例身份，不能只按型号跳页。

## 动态设备目录

Device Setup 是本机设备登记列表。每台设备的 Add、Edit、Test Connection、Diagnostics 和 Remove 入口等价；参数和可用操作由型号决定。远程设备配置只能查看，在所属电脑修改。连接远程 Host 不会将远程设备复制成新的本地设备记录。

Add New 的流程为 Category、Manufacturer and Model、Connection、Test Connection、Add and Save。目录包含 OSA、ESA、Oscilloscope、Function Generator、Power Meter、Piezo Controller 和 Custom；已有自制 Voltage Source 与 Gain Driver 放入 Custom 下的明确型号，不是通用原始命令入口。

没有已审阅适配器的分类或型号显示 Driver required。可以保留注册草稿和型号需求，但不能通过绑定通用 VISA、任意脚本、SCPI 输入框或成功 ping 来跳过驱动实现，并加入可控制的正式设备列表。不存在的厂家型号不人为填充为可运行选项。

型号目录使用稳定 model_id 和 driver_id，列出支持的连接 profile、必要依赖、身份验证方法、安全探测能力、公开操作、启动与关闭副作用。目录来自随程序发布的受信适配器，不远程下载或执行用户输入的模块。每次变更驱动或探测 profile 版本后，重新验证受影响的注册证据及自动检查授权。

### 连接配置

连接接口和访问方式分开。USB、Serial、GPIB 和 Ethernet 描述设备通道；VISA、串口协议、厂商 SDK 或特定网络协议描述访问方法。VISA 可访问多类资源，不能作为与 USB 或网线互斥的物理接口。[PyVISA 资源类型](https://pyvisa.readthedocs.io/en/latest/introduction/names.html)

串口 profile 只显示其需要的 COM 地址、波特率、数据位、校验、停止位及超时；已有 Voltage、Gain 和 MDT profile 沿用 115200 和各自协议。USB 转串口仍使用串口协议，不因 USB 插头而选择 USBTMC。CH340、CP210x 的 USB 身份用于提示候选端口，不能唯一证明仪器型号。

VISA profile 显示接口、资源地址、backend 和必要的超时或消息边界参数；Ethernet profile 还需要地址及具体协议，端口是否可填由型号决定。不能向所有设备暴露任意终止符、认证流程或端口参数。未完成型号文档核对和模拟协议验证的连接方式禁用；现有 GPIB AQ6370 路径不能仅改成 TCPIP 地址就宣称其网络协议已适配。

设备登记优先记录仪器自身的厂家、型号及序列号，并分别保存运输接口的 USB 序列号或地址。没有唯一仪器序列号时保存证据强度与操作者绑定，不声称已获得强身份。COM 号改变时，有稳定且唯一的运输身份才可找到新的候选端口；经身份复核前不能自动转移控制。

Host 和 worker 在打开资源前核验实例和规范资源预约。相同物理资源不能通过两个设备记录、VISA 别名、Serial 与 ASRL 两种访问入口，或 setup 与设备页重复持有；无法证明两个地址是否独立时拒绝同时会话。不同 Host 的本地资源命名独立，不能仅因 COM3 或同一 GPIB 字符串而发生跨 Host 冲突。预约只保护本应用和同进程合作驱动，不保证可抢占外部软件。

### 测试与正式登记

扫描资源、只读连接验证和可改变输出的可逆动作保持三个分别授权的阶段。Test Connection 使用型号经过审阅的身份与只读探测入口，确认设备、协议、依赖和资源释放。它不代表该仪器的所有操作都已实测，不自动开启电压、电流、TEC 或采纳位移基线。

当前 VoltageSource.connect 会发送全通道零，GainDriver.connect 可能触发联锁关断，不能把这些普通生命周期调用伪装成只读测试。型号没有安全只读探测入口时，显示 Manual verification required，并引导先进行独立诊断；只有明确批准相应生命周期副作用后才可创建受监管的真实会话。不能由 Add and Save 隐式执行该步骤。

新的探测入口若需要补入驱动，仍放在 Code/Utils，必须审阅打开端口的复位、DTR/RTS、握手、读取失败和关闭副作用；界面及服务器不得自行打开串口或 VISA 绕过驱动。没有得到只读保证时禁用自动主动探测，不以“不发送设定命令”冒充“不会改变设备”。

测试产生绑定 model_id、连接 profile、配置修订、设备身份、模式和探测版本的临时成功证据，有效期六十秒。字段改变、模式变化、身份不符或证据过期后，需要重新测试。模拟证据不能用于真实设备登记。Add and Save 只接受当前成功证据并进行原子配置写入；保存成功后才正式发布设备目录。

只读临时探测资源未确认释放时不能正式登记或重试另开会话，必须保留失败证据和资源责任。验证草稿预分配待登记设备 ID，并以当前配置摘要参与同一资源预约与责任调度；正式登记沿用该 ID，不能借未登记状态绕过容量和关闭责任。取消草稿先完成清理再退役 ID，不能在有未完成责任时更换身份或复用旧 ID。成功证据返回前确认只读探测资源已释放；明确批准保留的受监管会话不是临时探测，证据必须标出其会话及控制者。保存失败保留草稿及错误，不发布半条配置，也不把成功探测改写成成功保存。如果受监管会话仍存活，保存失败后的资源和安全清理责任仍须显式处理，不能丢掉会话对象。

### 配置和迁移

本机注册表使用 version=2，将 Host Settings、devices 和 setups 分开。每个设备包含 device_id、显示名、category、model_id、driver_id、connection_profile、必要连接参数、expected_identity、配置修订和在线检查策略。setup 以 setup_id 引用设备 ID。瞬时 ONLINE、测量值、控制租约、开放资源、Fiber 基线及 READY 状态不持久化为下一次启动的事实。

旧 version=1 的 role 地址和 Python 路径保留原始备份，再转换为 Imported drafts；默认 AQ6370 地址和从未验证的空槽位不直接变成已登记或在线设备。迁移不连接仪器，也不建立 Fiber 位移权限。配置损坏或未来版本无法识别时封锁写入并报告，不用空配置覆盖原文件。

编辑采用配置修订检查，不能由两个 GUI 最后写入者静默覆盖。改绑物理目标创建新设备 ID；旧 ID 保留退役标记和历史结果。删除或改绑前撤销共享、阻止新请求并完成该执行域已有责任及清理；释放不明时禁止删除，不能通过删配置清除资源保留。显示名称变更不改变物理身份或控制目标。

## 在线检查

Host 启动加载已登记配置，并按操作者为该设备明确启用的检查策略更新可用性。检查许可分为枚举资源和型号只读探测，分别绑定真实或模拟模式、设备身份、配置修订及探测版本。默认不主动打开端口；第一次启用对应阶段需明确授权。把检查策略写入配置是产品行为，不等于现在已获准在真实仪器上运行诊断。

已启用的枚举检查可以在启动时检查资源是否出现；它只产生 Detected 或 Not detected 证据。经过专属授权且 profile 已证明可安全打开和关闭的只读探测，才可在启动和定期检查中更新 ONLINE。配置、身份、探测版本或模式改变，旧授权失效。没有该能力的设备等待显式连接或人工诊断，不反复尝试有副作用的 connect。

已有驱动会话优先使用所属执行域的合并巡检和缓存，不能由后台另开资源测试。正在扫描、操作、清理或被其它软件占用时不抢占、不无限排队；分别报告 Busy、检查延后或未知。未知和 Busy 不自动等于物理离线。驱动已经授权的 watchdog 和安全联锁不因 UI 轮询暂停而停止。

新增的空闲主动检查默认三十秒一次，可关闭，不可设得短于十秒；失败按三十、六十、一百二十、三百秒退避，成功后恢复正常周期。每个设备最多一个检查责任，Host 只允许一项独立主动探测执行；启动任务错开，不为每个 GUI 新建线程或轮询。已连接驱动的既有安全巡检周期保持不变，不能用三十秒 UI 检查替代 Gain watchdog。

探测开始时固定设备 ID、配置修订、连接代次和 Host 启动身份，发布前再次匹配；旧配置的迟到成功不能标记新配置 ONLINE。检测到身份变化、外部移动或资源责任不明时封锁相关动作，沿用所属驱动的故障处理，不自动恢复输出或重新采纳基线。Voltage 故障归零和 Gain 电流优先关断规则不变；Fiber 故障保持压电输出，不能自动零压或回滚。

通信证据的有效期由 profile 明确给定，并携带实际采样时刻与年龄。检查失败保留最后成功证据并更新质量；通信失联、读回过期和释放不明是不同字段。自动检查不能构成控制租约，不执行自动接管、resume、重连或输出恢复。

## Fiber 设备与 Setup

两台 MDT693B 作为实体设备记录登记和显示，仍以序列号 2110148249-10 和 160721175410 确定左、右侧，不由 COM 顺序决定。它们与其它设备拥有相同的注册与状态入口，但真实 Fiber 运动始终经 Code/Setups/fiber_coupling.py，不能由设备页直接调用底层 MDT 运动操作。

Fiber Coupling 作为上层 setup，引用本机一侧或两侧设备 ID，保留实验室轴映射、MAX312D 名义换算、动作步长和显式基线规则。首版不建立跨 Host 复合 setup。控制器物理配置与 setup 坐标语义分开；删除某侧记录前先解除 setup 责任。setup 不要求两侧都在线才可登记已验证的一侧。

一个 Fiber setup 只有一个控制执行域，覆盖其引用的控制器及串口资源。控制器状态卡片指向此 setup 的使用入口，裸设备视图只提供诊断和配置，不另授予相冲突的普通运动控制权。一个实体设备不能同时属于两个活跃控制域，部分失败与权限丢失不能让另一页继续使用旧基线。远程 setup 动作同时核验 setup 与所有可能被动作或清理影响的子设备授权，只能观察某个控制器不意味着有权操纵整个 setup；发布状态时继续按可见范围过滤。

## 连接和共享

用户选择 `Connect Remote Computer`，输入另一台电脑的 Host 地址并进行配对。连接成功后，GUI 追加对方授权共享的设备，保留已有本地设备和其它远程设备。

连接方向按客户端分别建立。A 连接 B，不自动赋予 B 对 A 仪器的访问权，也不自动将 A 的设备加入 B 的 GUI。B 的本地 GUI 无需反向连接 A，就能同步看到 B 自己的仪器被 A 操作后的变化。需要 B 访问 A 时，再单独连接并授权。

保存远程地址不保存控制权、仪器连接权限或 Fiber 基线。重新打开 GUI 可以恢复观察订阅，但不自动申请控制，不打开设备，不恢复电压、电流、TEC 或位移命令。

只有本机操作者可以编辑本机仪器资源绑定、Python 路径、驱动配置和共享授权。远程 GUI 不能传入 COM 地址、VISA 地址、解释器路径或代码目录来更换目标。

## Tailscale 网络边界

网络接入的首选方案是 Tailscale Serve 的私有 HTTPS 反向代理：Host 网络入口只监听 `127.0.0.1:48160`，为本应用分配专用的 HTTPS 路径 `/yang-lab`，远程客户端使用完整的 `https://<host>.<tailnet>.ts.net/yang-lab` 地址。实际路径转发与事件通道必须通过代理集成测试，不能只以地址可访问作为验收。

Serve 支持将本地 HTTP 服务作为私有入口，并在 HTTPS 入口使用自动配置的证书。本应用选择 Serve 而不是公开服务的 Funnel。[Tailscale Serve](https://tailscale.com/docs/reference/tailscale-cli/serve)

部署 Serve 的 HTTPS 入口需要由网络管理员确认 HTTPS 已启用，并理解公开证书的名称会进入 Certificate Transparency 记录。Host 的网络名称不应包含个人信息或保密实验内容。证书名称公开不等于服务公开可访问。[HTTPS 证书说明](https://tailscale.com/docs/how-to/set-up-https-certificates)，[Serve 前置条件](https://tailscale.com/docs/features/tailscale-serve)

本地 GUI 使用带 Windows 用户访问限制的本机 IPC 接口，不依赖 Tailscale 在线。远程 HTTPS API 不包含本机管理入口。网络通信由 GUI 的 Rust 后端处理，WebView 不持有远程认证凭据或直接访问任意地址。

配置 Serve 前要读取现有配置，确认专用路径及端口没有冲突。不得运行全局 reset、改动已有映射、启用 Funnel、切换 Tailscale 账号、配置 exit node 或发布整个文件目录。Tailscale 和防火墙的任何写入均属于后续单独批准的部署操作。

Tailscale 的 grants 用来限制哪些身份可以到达 Host 入口；Host 自身仍需进行应用认证和设备授权，不能把网络可达视为设备控制权。[Tailscale grants](https://tailscale.com/docs/features/access-control/grants)

首版支持当前 Tailscale 网络中可达的 Host。普通客户端不能同时在多个 tailnet 上传输，因此不能声称本方案已解决私人网络与独立 Lab 网络的同时在线问题。跨网络时可另行选择共享指定电脑；这种共享并不开放整个对方网络，且有接收者身份和 tagged 客户端限制。网络组织方式由部署阶段确认，不在本轮改动已有私人网络。[账号切换](https://tailscale.com/docs/features/client/fast-user-switching)，[电脑共享](https://tailscale.com/docs/features/sharing)

## 配对和权限

共享默认关闭。本机操作者开启指定设备共享，选择观察或控制许可，再创建一次性配对凭据。配对凭据包含至少 128 位安全随机量，有效期五分钟，只能消费一次；一分钟内五次失败后暂停该来源的配对尝试。凭据不写入 URL 查询、普通日志或操作记录。

首次配对同时验证 HTTPS 证书、Host 身份和一次性凭据。GUI 固定保存 `host_id`；地址仍相同但身份变化时，必须重新由操作者确认，不能静默替换。

成功配对获得该客户端专属的至少 256 位随机认证凭据，保存于 Windows 凭据保护机制；普通配置只保存非秘密引用。Host 保存验证材料及授权范围，不保存可直接使用的明文凭据。认证凭据可以由本机操作者撤销，撤销立即使相关会话与控制权失效。

权限分为：

| 权限 | 允许的行为 |
| --- | --- |
| Observe | 查看获授权的目录、缓存状态、操作进度及采集结果 |
| Control | 有资格显式申请该设备控制权，取得后调用获准的设备操作 |
| Safe Stop | 请求该设备允许的安全停止，不要求当前普通控制权 |
| Local Manage | 通过受信本机 IPC 管理本机配置、共享和 Host 关闭 |

控制授权包含相同设备的 Safe Stop 权限；仅观察的客户端不能停止别人的操作。本机管理身份由 IPC 的操作系统访问检查建立，不接受网络消息中的 `local=true` 或自报管理员身份。

首版网络 `Safe Stop` 明确采用撤销该实例控制域并执行该域 disconnect 的流程，不保留可立即继续写入的控制权。正常面板上的电压归零、关电流等受控操作仍走既有驱动 API 和 STOP_HELD 恢复规则，不能把它们与网络控制权撤销混为一谈。

远程网络接口不提供任意 Python、终端、原始串口、SCPI、文件路径读写、全局 worker shutdown 或 Host 配置修改。操作必须从设备目录中的公开白名单映射到现有驱动 API，并继续执行 sensor capability 等底层门控。

## 设备身份和状态

设备键是 `host_id + device_id`，setup 使用独立的 `host_id + setup_id`。`host_id` 为持久化随机标识，设备显示名称和电脑名称可以修改，但不是权限标识。`device_id` 对一个已配置的设备条目稳定；改绑实体目标时创建新设备身份，使旧请求不能控制新仪器。客户端的 LOCAL 或 REMOTE 标签只由所属 Host 是否是本机判断；相同设备在 A 与 B 的 GUI 中可能有不同来源标签，但共用 B 发布的实际状态。

每次 Host 启动创建新的 `host_boot_id`，每个客户端连接创建新的 `client_session_id`。worker 的 `session_id`、实例的 `connection_id` 和 `epoch` 保留现有含义，v3 上下文另外绑定执行域 ID；网络控制权另有 `control_epoch`。配置修订、通信探测结果和控制代次都是不同字段，不能互相替代。

目录同时包含设备类型、显示名称、可用操作、连接状态、模拟或真实模式及控制域。设备卡片通过 control_domain_id 解析到独立设备域或其上层 setup 域；客户端不能自行用类型名决定调度域。Fiber 左右子视图共用 setup 控制者和基线证据，不拆成互相独立的运动控制权。

Host 发布读回值、设定值、命令目标、开关状态、连接状态、故障、控制者、操作阶段及结果引用。字段分别携带读取成功与否和样本年龄；未知值不是零或关闭。UI 不把命令成功当成物理输出证明，不把 Fiber 名义位移当成实测位置。

Host 负责合并与安排设备巡检，GUI 观察请求只读取缓存。增加 GUI 数量不增加串口或 VISA 轮询频率。现有 Gain 温度与关键状态巡检及驱动 watchdog 继续运行；某些驱动读取会触发安全联锁关断，不能承诺底层巡检绝对无输出副作用。

## 控制权与撤销

多个 GUI 可以观察同一台仪器，但每个设备控制域只能有一个普通操作控制者。本地 GUI 和远程 GUI 使用同一仲裁规则，不以最近一次点击覆盖另一个操作者。

控制者显式选择 `Acquire Control`。Host 创建不可预测的控制凭据，绑定客户端会话、设备域、Host 启动身份及当前控制代次。客户端每两秒续期，Host 上限为十秒；期限由 Host 的单调时钟决定，并在每次准入时复核，不能只依赖定时线程。

续期须建立在 GUI 会话仍存活、事件通道可消费及当前控制身份一致的条件上；后台连接管理器不得为已关闭或失去响应的 GUI 永久续期。Host 不得持有控制登记锁等待驱动、网络发送或普通日志 I/O，避免阻塞失效检查与安全请求。

普通操作必须同时满足控制资格、控制租约、目标身份、操作确认及该操作的驱动生命周期前提。已连接设备的普通输出动作需要驱动允许的就绪状态；connect 核验未占用的配置条目及预连接身份，resume 则遵守现有 STOP_HELD 恢复条件，不能把 READY 错误地作为这两项操作的前提。取得控制权不自动连接仪器、不自动 resume、不采纳 Fiber 基线、不使能输出。

当前控制者可显式释放。另一客户端只能请求接管；首版不强制抢占。本机操作者如需收回控制，先请求安全停止并处理旧责任，随后才可取得新控制权。

释放、过期、认证撤销、控制客户端丢失事件会话或 Host 恢复自系统休眠后，Host 首先封锁该控制域的新普通操作并推进控制代次，随后通过实例化后的安全调度提交该域的 disconnect。安全清理只影响这名控制者拥有的设备域，不关闭同类型的其它实例、其它控制者的设备或整个 Host。

撤销操作与向 worker 发送普通请求必须在同一设备域内排序。尚在 Host 队列中的旧请求直接失效；已经发送到 worker 的请求由 worker 的 disconnect 代次屏障作废尚未开始的调用。已进入驱动的调用不能凭网络取消强制打断，仍要等待其返回并完成最终清理。不能把 Host 撤销时刻描述成物理动作立即停止的时刻。

新控制权必须等旧调用责任结束、清理与资源释放确认后才可授予。失败或资源保留时继续封锁该域。下一操作者需要显式重新连接；不复用旧控制者的 Fiber 基线或继续其输出。

### 撤销后的设备处理

| 设备 | 通过驱动执行的清理 | 必须保留的事实 |
| --- | --- | --- |
| Voltage Source | 立即尝试全八通道归零，再释放资源 | 不等待正常 0.1 V ramp；零命令、遥测零证据与物理零是不同事实 |
| Gain Driver | 关电流，随后关 TEC，再释放资源 | 顺序不可倒置；字段可能未知，不能伪造 Off |
| Fiber Setup | 停止新动作，关闭 setup 会话并保持压电输出 | 不归零、不回滚；位置估计和动作基线失效 |
| OSA | 结束本会话调用并通过既有驱动关闭 | 关闭可能中止扫描，前面板测量参数不改写 |
| PM400 | 通过驱动正常关闭 | 不复位、不归零校准、不修改前面板测量设置 |

上述是已确认方向所采用的网络失联策略，不增加驱动输出权限。独立硬件联锁仍有必要：Host 崩溃、操作系统冻结、电脑断电或驱动永久阻塞时，软件不能保证真实输出已经安全。

## 操作确认和硬件阶段

连接 Host 只建立软件会话，返回配置目录和缓存状态，不因客户端接入执行仪器枚举、设备连接或硬件动作。Host 的已授权后台在线检查独立安排，不由每个新增 GUI 触发。

真实硬件继续遵守三个分别授权的阶段：枚举、连接、可逆动作。一次授权不自动覆盖下一阶段。操作确认必须显示所属电脑、具体设备、作用范围、参数与单位和已知副作用，并绑定当前客户端、控制权及设备连接身份。

Voltage 连接会归零全通道，不能标成只读；Gain 连接发现非法电流与 TEC 组合时可能安全关断。MDT 和 PM400 的正常连接与关闭按现有只读约束处理。协议不能把未知行为重新包装成纯读取。

需要操作者确认的操作先向 Host 准备请求。Host 返回绑定目标、参数摘要、当前权限代次及设备身份的一次性确认凭据，有效期六十秒；执行时核对凭据、原参数和当前身份，消费后不再接受第二个动作。准备请求只访问缓存和执行参数验证，不先做硬件动作。

确认凭据过期、参数改变、身份改变或权限失效时，GUI 必须重新展示确认。设备普通遥测更新不自动使确认失效；安全或连接身份变化必须使确认失效。执行时仍由驱动进行新鲜读回与最终安全检查。

故障清理和控制权失效后的既定安全关闭不等待新的 GUI 确认。针对 PM400 reset、zero/calibration、响应系数和 adapter 等操作，普通 Control 权限不能替代该次明确授权。

## 网络协议与命令责任

网络协议使用独立的版本号 `net_v=1`，采用 HTTPS 查询与命令入口、WSS 事件会话。所有消息严格验证字段、类型、单位、长度和有限数值；不兼容版本只允许显示错误，不能回退到无权限检查的协议。

执行消息携带客户端消息 ID、Host 身份、Host 启动身份、客户端会话、设备或 setup ID、配置修订、控制代次、worker v3 context、公开操作名、参数及所需确认凭据。客户端不能提供任意 worker method、适配器优先级或路径；Host 从登记记录解析真正的 driver_kind 和执行域。设备 ID、setup ID、上下文执行域与登记引用不一致时在调用前拒绝。

Host 先检查认证和共享范围，再查找同一请求键的原记录；重复请求只有参数摘要一致才返回原记录，不再次消费确认凭据或下发硬件动作。新请求继续检查控制凭据、准备确认、目标身份和容量，建立持久化操作责任记录后再提交给 worker。若记录不能安全落盘，普通动作在调用前拒绝；独立安全停止不能因为普通记录存储已满而被堵塞。

网络接收确认表示 Host 已接管这项请求，不表示仪器已执行或输出已达到目标。GUI 从事件或查询获得后续状态。worker 的 `rejected_before_call`、`superseded_before_call`、`completed`、`completed_readback_failed` 和 `failed_after_call_started` 原样保留，并分别映射到英文提示。

同一客户端会话和消息 ID 只对应一项操作。相同 ID 与相同参数重复到达时返回原记录，不再下发；同 ID 参数变化时拒绝。内部 worker ID 从全局请求键生成不超过 64 字符的独立 ID，不能直接转发不同 GUI 可能冲突的计数器。

去重保证针对本 Host 接管的请求，不承诺物理仪器协议的 exactly once。发送后断线或超时显示 `Outcome Unknown`，不自动重发动作、不自动 resume，也不生成新 ID 来重复旧操作。恢复网络后先查询原操作记录并同步读回状态。

Host 重启时，旧控制权、确认凭据和 GUI 会话全部失效。落盘记录中没有可信终态的旧操作恢复为未知，保留证据但绝不重新执行。worker 或驱动进程仍可能存活时，不自动重开仪器；需要本机操作者按资源恢复流程处理。

现有 worker 超时边界继续保留：action 180 秒、connect 或 disconnect 90 秒、status 5 秒，其它 RPC 30 秒。网络接收等待上限另设五秒，不用五秒网络超时去取消已经进入驱动的操作，也不因为网络延迟而擅自延长底层超时。

## 状态同步与有界负载

Host 启动身份内使用单调递增的事件序号。客户端建立事件会话时先收到一致的目录和状态快照，随后接收其后事件；先订阅再构造快照的缓冲责任由 Host 承担，不能在两步之间漏掉一次动作。

快照的一致性针对目录、权限和事件边界，不表示所有仪器或同一仪器的各字段是在同一瞬间测量。发布前按该客户端的授权过滤目录、状态、操作记录和结果，不直接广播完整内部 worker status。

序号缺口、乱序、Host 重启或过期事件触发重新同步。客户端在同步完成前封锁普通控制。设备旧身份的迟到结果可以作为历史证据显示，但不能更新新设备的控制界面或清除 UNKNOWN。

图表、读回状态、命令结果和控制者信息由 Host 发布；尚未提交的输入、游标位置、相机视角和本地导出路径留在各 GUI。别人操作后，当前草稿可以保留，但要标出其依据已改变并要求重确认，不能自动应用。

新鲜度使用 Host 的采样与发送单调时间、客户端接收后的时间增长，以及会话时钟探测所得的年龄区间，不能依靠两台电脑墙上时钟完全同步，也不能把未知传输延迟当作零。无法给出可信年龄上界时标成 `Freshness Unknown` 并禁止依赖该字段的普通动作。Host 执行前仍独立检查自己的新鲜度与驱动联锁；连接存活不代表每个测量字段都新鲜。

首版负载边界如下：

| 责任 | 上限和超限行为 |
| --- | --- |
| 一个 GUI 的 Host 连接 | 本地一个，远程最多十六个；拒绝更多连接 |
| 一个 Host 的 GUI 会话 | 最多十六个；拒绝超额会话，不影响既有连接 |
| 本地登记 | 最多六十四台实体设备、十六个 setup；运行执行域含临时验证域最多六十四个，复合 setup 占用子设备而非额外打开会话 |
| 普通操作 | 每个控制域最多一项未终态普通操作；Host 总数不超过现有三十一项普通请求名额，登记更多设备不提高并发写入上限 |
| 安全与终态责任 | 每个执行域最多三项递增安全意图；加三十一项普通、一个查询和一个全局关闭，上限为二百二十五项责任；回复队列上限二百二十六项含一个协议错误帧，普通容量不能占用安全保留额度 |
| 状态查询 | 每个 Host 合并为一项实际 worker status 查询，正常约每 2.5 秒刷新缓存 |
| 空闲主动探测 | 同一设备最多一项，整个 Host 同时执行一项；只使用明确授权的型号 profile，忙时延后，不无限堆积 |
| 控制心跳 | 每两秒一次，具有独立容量，不与普通动作或大结果排队 |
| 事件待发队列 | 每个客户端最多 256 项且总计不超过 1 MiB；遥测按设备合并，责任事件不丢弃 |
| 网络控制消息 | 单条不超过 64 KiB；超限在解析前拒绝 |
| 操作记录 | 最多 4096 条终态索引，正常保留 24 小时；未终态责任另受准入上限保护，不为新请求丢弃 |

慢客户端无法接收责任事件时，结束它的会话并要求重新取快照；不能丢掉停止或失败事件后继续显示正常控制。若它拥有控制权，会话失效同时触发上述撤销流程。到达容量限制时明确拒绝，不延长无限队列。

超过索引保留期的消息 ID 不能当成新动作重放。每个会话的普通命令采用严格递增序号，客户端串行完成网络准入，收到接收确认或查询确认后才提交下一序号；硬件执行仍异步，已准入的不同设备可以并行。Host 维护已接管水位，退役的旧序号返回 `Record Expired`，只允许核对状态。安全请求使用独立序号域和保留容量，不等待普通准入。Host 重启通过新启动身份拒绝整个旧会话。

光谱等大结果不放入状态事件队列。事件仅包含结果 ID、大小、内容校验和及采集身份；GUI 从有权限的只读 HTTPS 结果入口分块获取，每次获取都检查所属设备权限。单次结果上限 16 MiB，超过时返回明确的结果容量错误，不截断后冒充完整光谱。结果获取与下载不占用仪器控制队列。

## 关闭与恢复

Host 由本机操作者显式启动，不随网络连接自动启动，不自动建立可控制的仪器会话。启动后只按单独启用并仍有效的策略枚举或安全探测，不自动执行普通 connect。首版不安装开机服务、不启用无人值守自启动。Host 模拟或真实模式在启动时确定，变化需要有序关闭并重新启动，不能沿用旧身份或检查授权。

GUI 关闭与 Host 关闭分开。GUI 没有控制权时，关闭只结束该 GUI 会话，不断开别人的设备。GUI 持有控制权时，默认先释放其控制域并展示清理报告；失败时保留窗口和未知证据，不将失败报告改写成成功。独立 Host 继续运行，处理其它 GUI 的订阅和控制。

`Disconnect Remote Computer` 同样只释放当前 GUI 在该 Host 上持有的控制域并结束观察会话，不是远程 Host 全局 shutdown。只观察的客户端可以立即断开。

`Stop Local Host` 是单独的本机管理操作。确认框列出本机所有受影响的连接与控制者；确认后 Host 封锁新操作、撤销全部本地控制域，调用既有全局安全关闭流程。没有完整清理和资源释放证据时保留 Host 的管理状态，允许核对与重试，不自动强杀 worker。

Host 必须提供持久的本机运行标识及重新打开管理窗口的入口。退出 GUI 后仍在运行的 Host 不能隐藏成无人知晓的进程；打包启动独立辅助进程时使用隐藏进程窗口，并由应用管理入口明确显示运行状态。

系统强制结束、Host 崩溃和断电不是正常关闭。再次启动先报告此前未完成责任和输出未知，不能把旧资源预约消失或进程退出当成零电压、关电流或成功释放证明。

## 驱动和 setup 约束

网络层不得提高任何现有上限。Voltage 仍为 0–14 V，正常步进不大于 0.1 V 且间隔至少 50 ms；失败关闭立即尝试全通道零。Gain 仍为 0–200 mA、15–40 degC，并由驱动执行 TEC 开启及目标温度正负 0.2 degC 连续五秒稳定联锁，先关电流再关 TEC。

OSA 沿用前面板设置。PM400 保留设置、按探头能力门控，并继续保护同一规范 VISA 资源的合作会话；不同资源和不同 Host 的设备不能因地址文本相同而相互冲突。借用 VISA manager 时，所属进程需保持它存活直到全部依赖驱动确认释放。

Fiber 仍通过 setup 控制，不直接调用 MDT693B。左侧绑定 `2110148249-10`，右侧绑定 `160721175410`，沿用实验室坐标及既有轴映射；75 V 上限、靠近芯片每次 0.2 um、其它方向每轴 1.0 um 的限制不变。所有 GUI 显示同一 Host 会话的开环估计，不能各自建立互相矛盾的基线。

连接、恢复、控制权转移或网络恢复不会自动建立位移权限。权限丢失、外部手动移动或部分失败后停止并保持，作废估计；名义 MAX312D 换算与操作者基线采纳仍需各自明确授权。不自动归零，不自动回滚。

## 代码和数据位置

Host 与网络通信代码放在现有 `App` 内，独立 Host 入口及共享运行时在 Rust 源码中；worker 保持 `App/worker`。型号目录、动态注册表和实例调度也属于 App 层；UI 按 host_id 与 device_id 创建状态、输入草稿、图表、结果及控制对象，不能继续以一个全局 role 对象覆盖同机或来自多个 Host 的仪器。

仪器驱动保持在 `Code/Utils`，setup 保持在 `Code/Setups`；网络服务器、认证、缓存或结果不放入驱动目录。网络离线测试与 worker 模拟测试放在 `App/tests`。真正的硬件验证仍由 `Code/Debugs` 中的诊断入口执行，不把模拟预览改成真实远程控制服务器。

每个 Host 的非秘密配置保存于本机应用配置目录，认证材料使用 Windows 凭据保护。操作审计与一般 GUI 采集结果默认进入所属电脑的 `Result/console/<host_id>`；实验输出仍进入 `Result/<name>`。远程 GUI 可显式导出本地副本，但文件路径不成为网络执行参数。

`reference_code` 和现有实验配置不改动。整个设计及后续实现均不重新开启 AWS 设置、不删除此前安装工具、不改动私人 Tailscale 配置，不自动合入 main。

## 验收条件

实施先进行纯离线单元和协议测试，再进行两个模拟 Host 的网络集成，最后才可分别批准真实硬件三个阶段。所有项目 Python 命令使用各电脑的 Anaconda VISA 环境；测试启动明确使用 `--simulate`。

验收必须覆盖：

1. A 的本地仪器在连接 B 后仍可显示和操作，B 的设备以明确的远程来源追加。
2. A 操作 B 的模拟设备时只有 worker B 被调用，两个 GUI 收到同一操作 ID、阶段及状态；B 本地操作也更新 A。
3. 两个 Host 各有同类型仪器或相同 VISA 地址文本时，状态、命令、图表、恢复和关闭互不串台。
4. 观察者不能执行硬件调用；两个控制申请只能有一个成功；本地操作者也不能绕过仲裁。
5. 过期凭据、错误 Host、错误启动身份、旧连接 context、旧 control_epoch、参数篡改和重复请求不能产生额外动作。
6. 控制者断网、窗口崩溃、主动释放、权限撤销及系统恢复均封锁新普通动作，清理失败后不能接管或自动恢复。
7. 在 Host 队列、worker 已准入队列和驱动已开始三个位置撤销控制，分别验证未发送拒绝、旧代次作废和最终清理责任；不得只测试空闲断线。
8. 迟到动作或状态回复不能改写新连接状态、解除 UNKNOWN 或恢复旧 Fiber 基线；沿用现有恢复竞态回归。
9. 普通队列饱和、慢 GUI 和大光谱下载不会堵塞心跳、实例安全入口或本机停止 Host 入口。
10. 丢失接收确认后查询原操作，而不重新下发；Host 重启将未终态记录保留为未知，不重放。
11. 关闭观察 GUI 不影响他人设备；关闭控制 GUI 只清理自己的控制域；停止本机 Host 才清理全部本机设备。
12. Voltage、Gain、Fiber、OSA 和 PM400 的清理使用驱动公开接口，顺序及保持规则逐项通过故障注入测试。
13. 配对失败、证书错误、代理路径错误、身份更换、端口占用或旧 Host 仍存活时失败封锁，不回退到明文远程访问或第二套驱动实例。
14. Host 与 GUI 英文身份提示、过期状态、错误阶段、控制者和模拟标识经过原生窗口验证；网页模拟不能替代原生验收。
15. 上述离线验收通过后，Tailscale 接入先使用两个模拟 Host；真实仪器枚举、连接、可逆动作仍各自单独取得批准，并区分软件结果、资源释放证据与物理测量。
16. 同一 Host 的两台模拟 AQ6370、两台 Gain 和两台 Voltage 分别拥有状态、读回证据、请求代次与清理责任；对一台失联、删除、停止或恢复不影响另一台，旧身份迟到结果不能串台。
17. Add New 按目录限制连接 profile，无适配器型号仅保留草稿；测试失败、身份错误、配置改变、证据过期、保存失败和临时资源未释放时不能正式登记，模拟验证不能用于真实登记。
18. 旧配置迁移保留原始内容，不生成已验证默认设备；损坏配置、并发编辑、物理目标改绑和删除失败不丢失责任或误写其它记录。
19. 自动检查只执行已批准的枚举或安全探测；无授权、忙、端口占用、DTR/RTS 风险、设备重插及配置变化分别有故障注入测试，不偷偷调用会归零的 Voltage connect、Gain 生命周期关断或 MDT 零压操作。
20. Overview 按实体设备统计本地和远程设备，不按类型或重复 setup 计数；LOCAL 与 REMOTE、ONLINE 与 OFFLINE、输出与控制权分别显示。远程 Host 在线不代表其仪器在线，远程 Host 断线不证明物理输出关闭。
21. 卡片和来源或状态标签都导航到精确实例；键盘可用，离线可查看。点击不产生硬件调用，未登记设备不生成假卡片，许可撤销封锁旧页面。
22. 原生窗口所有页面、控件、通知、图表和模型背景为浅色，英文标签无遗漏；必要安全确认、未知和未释放提示仍可见。第一阶段不制造虚假的远程成功状态。
23. v2 和 v3 严格分版，旧协议不会获得新实例权限；v3 的字段篡改、未知实例、目录绑定变化及饱和状态分别验证。将既有等待旧调用、关闭最终 pass、恢复竞态、终态保留和进程退出证据回归扩展到同类型多个实例。
