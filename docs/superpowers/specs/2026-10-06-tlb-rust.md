# TLB-6700 Rust driver migration

The first migration boundary moves all production TLB-6700 SDK transactions, identity validation, status parsing, command authorization, shared-bus ownership and preserving release into a reusable Rust driver in Code/Utils/tlb_native. Existing App scheduling and panels continue to use the same driver contract through a private bounded child-process adapter. Python orchestration remains in this stage; removal of that orchestration is a subsequent migration, not a claim of this stage.

No backend choice is exposed. Production never silently falls back to ctypes. Explicit injected finite transports remain offline-only test seams. Missing native binary is an actionable error. A single native process serializes every SDK call and shares the SDK across distinct controller serials; duplicate sessions fail. A cross-process owner guard prevents a stranded child from allowing another cooperating Rust owner to open the SDK. Connect, enumerate, status and normal close perform no setting changes. Cleanup failures retain ownership and faulted sessions cannot perform ordinary operations. A timeout or lost response is unknown, never grounds for automatic replay or forced process termination.

Control preserves reviewed standard head envelopes, explicit confirmation, fresh Remote/busy checks, Tracking before wavelength changes, and output-off while busy. Suffixed 6722-P remains unreviewed and read-only except expressly authorized output-off. Firmware packets use mutable 64-byte backing, ASCII byte length excluding NUL, first CRLF framing and at most one retry for reviewed getters only.

The native executable is packaged alongside the App, located by a fixed package/source path, and never downloaded at runtime. Only the existing authorized read-only stages may be exercised on connected hardware. Offline transport and process tests precede hardware. No emission, setpoint, Remote/Local or installer tests on hardware.
