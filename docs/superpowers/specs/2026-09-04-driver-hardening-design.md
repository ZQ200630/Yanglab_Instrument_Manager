# 底层驱动与会话加固设计

日期：2026-09-04。

状态：用户于 2026-09-04 确认本设计，作为实施依据。实施与验收进度见对应计划。

## 1. 目标与边界

修复 Gain 稳定时长、共享 VISA 生命周期、OSA 关闭失败三个已离线复现的问题，随后提取通用会话协调，明确电压归零证据，补齐环境和验收文档。保留现有 Python Driver → Setup → Experiment 分层。

本轮仅允许代码、文档和离线验证。不枚举、不连接、不操作实际仪器，不修改 Anaconda VISA 环境，不安装或升级依赖，不改实验参数和结果，不改 reference_code，不建立 Tauri、GUI、常驻服务或自动实验。

实测位移标定、探头与固件功能验收、硬件失联保护验证均属于后续分别授权的工作，不能用模拟测试代替。

所有现有 AGENTS.md 安全限制继续有效。尤其是电压源 0–14 V、Gain 0–200 mA 与 15–40 °C、MDT 75 V，以及 Piezo 故障停住保持、绝不自动归零。

## 2. 审查依据

2026-09-04，在 VISA 环境运行四个底层测试模块，共 658 项通过。额外使用真实 PyVISA ResourceManager 实现及模拟底层传输，复现：

1. OSA 与 PM400 共享同一个管理器，OSA.close() 会关闭 PM400 的资源，但 PM400 缓存状态仍是 READY。
2. OSA 资源及管理器关闭均抛异常时，驱动仍清空句柄并报告 DISCONNECTED。
3. Gain 的稳定谓词接受时间戳 100、101、102、103、104 秒，即只有 4 秒跨度的五个采样点。

代码审查还发现：跨仪器 safe_shutdown 位于 sil_hysteresis 实验模块，sil_repeat 从该实验导入；电压源把零帧完整写入标记为 shutdown_zero_confirmed；Fiber 配置十二个方向系数仍为 nominal_MAX312D，标定日期为空。

这些证据只支持相应软件结论，不证明任何仪器当前物理状态或硬件侧保护能力。

## 3. 方案选择

比较三种路径：

- 仅局部补丁：变更最少，但共享生命周期与跨实验依赖问题容易继续重复。
- 小型共享 VISA 管理层加通用会话层：推荐。保留现有仪器 API，只提取真正共享的所有权、关断与证据逻辑。
- 独立控制进程或常驻服务：需要新增通信、部署与进程监督机制，本轮不采用。

不建立包罗所有仪器操作的通用基类。协议、限值、温控与设备故障状态机仍由各自驱动负责。

## 4. Gain：用实际时间跨度证明稳定

- 温度样本仍来自现有每秒 watchdog，不以 wait_stable() 调用次数积累证据。
- 从本次稳定区间的首个有效样本开始，必须有至少 6 个有效采样点，首尾单调时钟跨度至少 5.0 秒。
- 保留相邻有效样本的现有最小间隔、最大允许间隔和证据新鲜度限制。调度延迟不能用少量离散样本冒充连续稳定。
- TEC 关闭、目标改变、温度越出目标 ±0.2 °C、通信失败、采样间隔过大、关闭或故障，均重置对应稳定证据。
- enable_current() 保留实际 TEC、当前设定及温度的临门复查和 epoch 一致性检查。
- 不改变温度异常关断阈值，不自动开启或恢复电流。

回归必须覆盖：五点四秒拒绝、六点五秒接受、不足五秒拒绝、断档和目标改变重置、旧证据拒绝、并发关闭优先于开启。

## 5. VISA：资源连接与管理器分别拥有生命周期

新增 Code/Utils/visa.py，供 OSA 与 PM400 共同使用。

### 5.1 所有权约定

- 驱动拥有自己打开的 instrument resource；同一规范化资源在项目内不得重复占用。
- 工厂取得的管理器通过共享租约登记。登记依据实际管理器对象身份，不能依据工厂函数身份；不同工厂返回同一管理器也必须共享计数。
- 关闭一个驱动只能关闭它自己的 instrument resource，并释放自己的管理器租约。只有最后一个项目管理的租约释放后才允许关闭项目拥有的管理器。
- 显式注入的 resource_manager 为借用对象，驱动不得关闭它。OSA 增加与 PM400 一致的可选关键字参数，原有位置参数顺序保持不变。
- 同一管理器既被借用又被工厂返回时，优先遵守外部所有权，不能借工厂路径关闭外部管理器。
- 与项目外代码共享管理器时，调用方必须使用显式借用方式并负责管理器最终关闭。不能声称能防止外部代码直接调用 manager.close() 或跨进程抢占。

### 5.2 并发与失败

- 登记、释放、最后租约关闭和重新登记之间具有明确互斥关系，不允许关闭中的管理器被重新分配。
- 全局登记锁只保护内存元数据，不跨仪器 I/O、重试等待、线程 join 或管理器关闭调用持有。
- 设备资源或其 helper 尚未确认释放时，保留资源占用和租约。失败不能靠删除登记项伪装成已释放。
- 管理器关闭失败或超时保留可追踪的所有权和错误；后续显式清理可以继续处理，不能自动反复启动关闭线程。
- 保留 PM400 现有 helper 有界等待、晚完成回收和 fault generation 保护；替换其管理器关闭动作，不削弱资源自身的安全逻辑。
- OSA 与 PM400 共用资源规范化及占用登记；VISA 完整名、标准缩写和 backend 可解析别名须指向同一登记目标。规范化失败应在打开设备前明确报错，不按猜测打开另一个目标。

验证必须包括真实 PyVISA 管理器语义加模拟 backend，而不仅是各自互不相关的 FakeResourceManager。

## 6. OSA：串行事务、取消与真实清理状态

- connect/acquire/close 增加生命周期保护和采集事务互斥。重复 connect 仍幂等；同一实例不得并行采集，同一资源不得由两个实例同时占用。
- 不修改面板测量参数，不新增自动扫参、复位或重新配置。保留原有采集、谱线校验与有限重试能力。
- close 先发布关闭/取消意图。旧采集即使稍后返回，也不能重新发布 READY 或成功谱线；下一轮重试不能在关闭后发起扫描。
- 正常清理顺序为停止本驱动采集、关闭本设备资源、释放共享管理器租约。
- 清理仅在实际成功且无未完成调用持有对象后清空对应句柄。未解决清理进入 FAULT，保留 cleanup_error 和对象；拒绝重新 connect 直到显式清理完成。
- 增加 close_timeout，默认 2.0 秒，只允许正有限值。close 使用单调时钟总预算；遇到不响应的底层调用，超时后返回带证据的故障，而非无限等候或假报成功。
- 有界 helper 必须可追踪、可回收，不允许每次重试都累积新线程；Python 无法强杀底层调用时明确保留未解决状态。
- 操作原异常及 KeyboardInterrupt/SystemExit 不被清理异常覆盖。无原异常时，关闭失败向调用方抛出；有原异常时，将附属清理错误留在驱动和异常证据中。

回归包括部分连接失败、同时采集/关闭、底层读或关闭卡住、晚完成、资源和管理器双关闭失败、显式再次清理、异常保真及面板设置不变。

## 7. 电压源：发送成功不等于实测归零

- 保留 zero(emergency=True) 的立即写零行为，不在紧急写零路径等待遥测。不得因此延迟 Gain 的电流关闭。
- 新增只读、不可变 ZeroEvidence，对外区分 command_sent、measured_zero 和 unknown；记录本次零帧发送时间、关联遥测时间与八通道电压。
- 完整写入零帧只能证明 command_sent。只有本次命令之后得到的新鲜八通道遥测全部满足现有归零容差，才证明 measured_zero。
- 新的非零命令、失败或通信证据失效使旧归零确认失效；禁止用历史零读数确认当前输出。
- 正常 close 在发出零帧后允许最多 1.0 秒等待相关遥测，然后无论确认是否成功都继续尝试关闭串口和回收线程。不能因等待遥测而跳过资源清理。
- 未得到相关遥测时对外保留 unknown 和清理故障，不能记录“实测归零成功”。已确认关闭的串口不必为了保留故障证据继续保留活动句柄。
- 保持已有调用签名与零电压安全策略，不新增输出恢复或重放命令。

回归包括写成功但无遥测、命令前旧零帧、命令后非零帧、新鲜全零、断线、再次设非零、等待被取消，以及未知输出时仍释放可释放的资源。

## 8. 通用会话：只协调，不绕过驱动

新增 Code/Setups/session.py。该层不直接使用 serial 或 pyvisa，也不导入任何具体实验模块。

### 8.1 边界与兼容

- InstrumentSession 持有调用方明确交付的可选 OSA、Voltage Source、Gain、PM400 与 FiberCouplingSetup；没有交付的设备不会被发现、构造或连接。
- 构造无硬件副作用。connect 明确调用各驱动既有 connect；Voltage Source 的启动归零不能被称作只读连接，诊断三阶段授权规则照常适用。
- 连接失败也清理已取得的对象，原始连接异常保留。
- 先提供与原 safe_shutdown 调用兼容的通用函数，再让两个实验从 session 模块直接导入；旧实验模块可保留兼容转发。不得改变扫描顺序、实验配置、数据格式、分析或结果恢复语义。
- Session 构造可用于离线替身测试，但替身和测试专用功能不得进入真实驱动的生产分支。

### 8.2 关断、健康检查和停止

- 统一关断顺序：电压源立即写零 → Gain 关电流 → Gain 关 TEC → 关闭 Gain 与电压源 → 关闭采集设备 → 关闭 Fiber Setup 并保持电压。
- 对每个步骤独立捕获清理失败，继续尝试其余步骤；不把 Piezo 归零当作通用清理。
- CleanupReport 保存每个步骤的成功、失败、未知输出证据及未释放对象，日志写入失败不能跳过安全动作。
- request_stop() 只发布停止意图，不做 I/O。check_health() 在实验明确的检查点检查停止请求及驱动公开状态，故障作为异常返回，由 finally/context manager 执行统一关断。
- 检查点放在连接后、每次输出修改前及采集返回后。未获新鲜遥测的状态必须标注为缓存信息，不能冒充实时物理状态。
- 本轮不添加常驻监督线程，不承诺在任意阻塞调用中立即跨仪器关断。驱动已有 watchdog 仍承担各自保护；该限制在文档中明确说明。
- 原始操作异常保持为主异常，CleanupReport 作为附属证据；没有主异常且清理失败时，向调用方报告清理失败。

测试覆盖任意可选设备组合、部分连接、重复 close、每个关断步骤分别失败、多个同时失败、日志失败、停止与检查点、保留原异常，以及 Fiber 关闭从不触发归零。
