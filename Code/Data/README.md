# yang-data

Native, hardware-independent waveform evidence and analysis. This crate has no instrument, UI, Python, or Anaconda dependency. The root waveform structs implement frozen contract v1; sample arrays use explicit externally tagged serde variants (`u8`, `i8`, `u16`, `i16`, `f64`). Do not send full records or raw arrays in UI/status RPCs.

Calibration uses `(absolute_index - x_reference) * x_increment_s + x_origin_s` and `(raw - y_reference) * y_increment_v + y_origin`. Each channel owns its axis. `calibrated` yields absolute sample index, seconds, and volts. `reduce_viewport` returns at most 8192 points, retaining actual extrema indices and endpoints; it is only a display operation.

`analyze` operates on original samples. Single Drop v1 uses a positive-width inverted Lorentzian with a bounded Levenberg-Marquardt solve. Scan speed is `2 * ramp_hz * excursion_pm` in pm/s; fitted center is measured from ROI start, FWHM is pm, and Q is `wavelength_nm * 1000 / fwhm_pm`. Fitting uses at most 20,001 uniformly sampled original indices including the global minimum; its residual statistics refer to those samples. This explicit fitting policy is recorded in result parameters. Curve X values remain absolute sample indices and are bounded to 8192.

`analyze_with_cancel` checks cancellation during raw validation, ROI scans, half-height search, FSR basins/subset regression and every fit iteration. `DataStore::metadata` reads committed metadata without raw arrays. `viewport_with_cancel` streams only the chosen raw channel through 16KiB chunks plus bounded extrema buckets, verifies the complete payload SHA-256, and returns no result on corruption/cancellation. Metadata/history reads stay usable during delayed raw scans. `load_with_cancel`, `save_with_cancel`, `import_path_with_cancel` and `export_records_with_cancel` expose confirmed native checkpoints for background jobs.

FSR v1 detects unsmoothed local dips, ranks conservative prominence using maxima in adjacent dip basins, applies sample-distance suppression, then scores contiguous subsets by `r_squared * dip_count`, matching the legacy subset scoring policy. It reports positive spacing in source samples and nm from the supplied scan speed. Candidate dip count is bounded to 4096; overflow is an explicit error. This implementation is versioned and does not claim numerical identity with SciPy's prominence calculation.

`DataStore` keeps immutable SHA-256-named raw NPY files and append-only, schema-checked metadata commits under record IDs. Names are labels, never paths. Each commit is published by a same-directory rename after file sync; unfinished `.part` files are ignored. Previously committed metadata remains available after an interrupted save. Labels can change without loading or rewriting raw data. Existing frame samples/calibration cannot be replaced under the same identity. Removal moves a record into `.trash` for recovery. Instances targeting the same canonical root serialize in one process; callers must coordinate separate processes that share a store root.

`append_frame` validates and writes only the newly completed frame, preserving prior immutable payload refs and the latest labels/analyses. It rejects duplicate frame IDs. `append_analysis` atomically adds validated results to the latest manifest. `finalize_record_source` updates only an experiment's terminal `run_status`, requires matching immutable provenance, and preserves operator edits/concurrent analyses without touching raw payloads. Metadata commits are full bounded snapshots (16MiB default), so many-frame callers still incur increasing metadata serialization, but never quadratic raw-data rewriting.

Import limits bound compressed bytes, total uncompressed bytes, member bytes, metadata bytes, member count, decoded allocation size, records, frames, and samples per channel. ZIP central directories are checked before index allocation. Archives are never extracted. Supported ZIP methods are Stored/Deflate; encrypted, split, ZIP64, symlink, duplicate, traversal and explicit directory entries are rejected. NPY v1/v2/v3 numeric vectors accept signed/unsigned 8/16-bit and float32/64, both endian orders; float32 converts to F64 with its original dtype in provenance. Object/pickle, structured and multidimensional arrays are rejected. Native representation supports up to 250M points; the configured byte budget remains a separate, usually smaller bound.

Legacy `.db` imports read `database.json` and referenced NPY files. The actual NPY dtype overrides conflicting legacy metadata with a warning. Legacy ADC-origin calibration is normalized, and original metadata/convention is retained. Unpacked `database.json` equivalents are supported with confined references. CSV imports expect `Time (us),CH1 (V),...`; NPZ imports expect `time_us`, Unicode/byte `channel_names`, and per-channel calibrated voltages. Nonuniform time axes cannot be represented by v1's linear calibration and are rejected explicitly. Imported records have historical provenance and no hardware authority.

CSV exports require identical channel lengths and axes; unequal axes report a per-file error. NPZ exports use legacy keys for shared axes and `<channel>__time_us` arrays for unequal axes. CSV/NPZ values are calibrated once, with metadata/analysis JSON sidecars. Native export produces a self-contained `.db` ZIP with versioned `database.json`, raw NPY payloads, checksums, calibration, provenance and analyses. Native exports are raw-preserving; CSV/NPZ are calibrated views. Output names are sanitized, ID-based and collision-safe. Batch reports retain each file's success or error.

Run `cargo test -p yang-data --offline --locked` from the workspace with its configured native Cargo environment. Test fixtures are generated only inside tests and never represent hardware captures.
